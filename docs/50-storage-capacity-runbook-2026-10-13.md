## 写入者矩阵

| 写入入口 | 当前保护 | 不覆盖的边界 | 操作要求 |
| --- | --- | --- | --- |
| API `modules/media/r2Push.ts` | `guardedR2Upload`，账户全集盘点与本机锁 | 其他主机/控制台/其他项目 | 同账户的 API 和 CLI 使用同一 TAO_R2_CAPACITY_DIR |
| `sync-media-r2.mjs` | 每次 Put 前按完整文件预约 | 磁盘媒体增长及其他主机 | 批量开始前重新全账户盘点，失败停止 |
| `sync-classics-release.mjs` | 同一容量保护 | 其他项目写入 | 启动前检查全部桶与 pending multipart |
| `public-audio-store.mjs`，直接 R2 | 同一容量保护 | 绕过工具的 S3 写入 | 只用限制到用途的密钥，避免新入口绕过保护 |
| 音频 Worker 网关/迁移 | 本机预约，5.4GB 桶阈值、内容哈希与回源读取验证 | 账户其他桶、绕过网关的 multipart 与主机 | 专用账户保持受控写入；发现新桶或未知容量时停止本项目上传并查明 |
| `backup-to-r2.mjs` | 实际按 BACKUP_* 上传 B2 | B2 额度与存储、派生媒体缺失 | 不因文件名误判它仍写 R2；备份成功不等于恢复通过 |
| TaoStudio cases/image-lab | 本轮未修改 | 可绕过本机 TaoRead 锁 | 接入共同预算前不得宣称账户永久不超 10GB |
| 其他主机、手工、控制台、外部密钥 | 本轮无法强制拦截 | 全部 | 限制写入者或建集中写网关后再作全局保证 |

8GB 预警，预计达到 9GB 即拒绝受保护 R2 写入；保留至少 1GB 安全余量。预留按上传全字节计算（覆盖也先全额预约），失败不立即退回未知预约。本机盘点缓存最多 60 秒；无法完整列桶/列页/列 multipart 时关闭上传。崩溃遗留锁不自动破锁，需查清对应进程和上传结果后处理。

## 操作步骤

1. 从明确的生产配置目录运行只读 `product-ops-evidence.mjs --config-dir=... --output=...`。配置不进入仓库、输出和命令日志；不要打印原始凭据或供应商错误。
2. 运营服务设置 `TAO_OPS_EVIDENCE_PATH` 为此受控快照的绝对路径。页面能区分缺少、无效、过期和已核实范围。此变量只供展示；上传守卫仍自己盘点，不能以页面绿色代替守卫。
3. 批量生成前核对旧账户所有桶和分块、新账户桶列表及独立分块状态、增长来源、待上传完整字节与阈值。缺权限/分页失败/容量未知均停止，不以当前桶尺寸推算全账户。
4. 每个新增写入者应登记账户、桶、身份范围、所在主机、最大批次和是否绕过集中入口。只有所有入口受控并有全账户检查，才可评估全局预算服务。
5. 接近阈值优先停止新增非必要生成，核查失败任务与分块残留，准备可复核清理清单。任何对象或备份删除先满足对应恢复与引用验证，不能按大小直接删。
6. 新快照有新桶/快速增长/未知上传时停止相应项目批量上传；调查真正写入者。不要自动删除其他项目对象来腾空间。

验收剩余：其他项目/其他主机统一控制、新账户即时独立 multipart 盘点和真实增长监测。当前采样低于 10GB，**本轮未实现账户级永久硬限制**。
