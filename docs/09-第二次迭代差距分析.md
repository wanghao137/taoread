## 0. 第一性原理：桃阅读到底要补什么

先把「差距」这个词的定义锚定，避免拿竞品清单当需求文档。

**桃阅读的第一性**（docs/02 §1.1/§1.5）：
> 孩子在「今晚读什么」里**自主选书**，家长拿到「讲什么、问什么」的**脚手架**，共读时光与金句被**收藏**，全家每周看见自己的**阅读足迹**。

北极星指标：**孩子每周自主发起共读的次数**。反指标：孩子单次屏幕时长、家长每周维护成本。

因此一条差距算不算「真差距」，判据是三问：

1. **自主性**：它是否把选择权/操作权交还给孩子？（→ 增加北极星）
2. **脚手架**：它是否降低家长「不会讲、看不见」的门槛？（→ 降低反指标）
3. **动机纯度**：它是靠**内在动机**（好奇、成就、亲情）还是**外部枷锁**（积分、焦虑、连胜）驱动？

第三问是淘汰器：调研里大量「行业标配」（积分商城、打卡对赌、看视频解锁时长、连胜火苗、虚拟宠物兑换）在第三问上直接出局——它们正是 docs/02 §3.4 负向清单存在的理由，也是 Scholastic 报告转引的专家结论「**nagging a child to read will surely turn it off**」所警告的方向。**这些不是差距，是护城河的另一侧**。

**由此，本轮只补三类差距**：
- **A 类（必须补）**：行业标配，且通过三问判据——缺了会被家长判为「不专业」
- **B 类（补了出彩）**：通过三问判据的差异化机会，且现有架构能低成本承接
- **C 类（代码缺陷）**：v2 已实现但行为错误/数据断层——无论竞品如何都必须修

| 少年得到 | 断点续播（底部「正在播放」） | 可学 |

### 1.2 国际产品的「及格线」与「机会」

国际一线的**入场券**（调研原文总结）：
> 4 个儿童档案 + Read-To-Me 专业配音 + 词典查词 + 读后问答 + 家长报告 + 离线 + 分级筛选 + 徽章体系

**能拉开差距的三件事**：
1. **亲人原声朗读**（Vooks Storyteller / Yoto Make Your Own / Tonies Creative 都是碎片化，没人做成一等公民）——击中 92% 家长 / 86% 孩子视共读为 special time、83% 孩子以父母为阅读榜样
2. **中文分级标准（T-Level）**——中文世界没有家长可感知的 Lexile
3. **「9 岁悬崖」防御**——8 岁 57% → 9 岁 35%，且 8–12 岁缺同龄人发现机制

### 1.3 Scholastic 研究对本轮设计的直接约束

- **唠叨会彻底毁掉阅读动机** → 所有提醒/目标必须温和、可关闭、默认私密
- **83% 孩子以父母为阅读榜样** → 把「家长在场」做成产品特性（脚手架、亲人原声），而不是把家长做成监工
- **90% 家长认为书创造对话机会、59% 用书帮孩子处理情绪** → 阅读后附「亲子谈话卡片」是刚需，不是增值
- **徽章只庆祝「读了什么」而非「连续多少天」** → 现有成就体系（夜灯第 N 晚 / 最长连续）需审视：**「最长连续」是 streak 变体，按此约束应弱化或改文案**

## 2. 桃阅读 v2 现状（自证基线）

- 家长端：书架管理（屏蔽）、周报、共读卡（模板版）

## 4. 补齐计划（按验收日 2026-09-20 倒排）

### 4.1 优先级原则

- **P0 = 验收日前必须完成**：A 类全部 + B1 + C 类全部。这些直接决定「最优秀、最好看」的观感和数据正确性。
- **P1 = 验收日前尽力**：B2 语音搜索、B6 听书模式、B3 成就文案审查。
- **P2 = 验收后**：B4 主题书单、B5 T-Level、A5 离线缓存、A4 内容域黑名单完整版。

### 4.2 P0 任务卡

> 每张卡：差距编号 → 交付物 → 验收方式（可测）

**P0-1（A1）哄睡定时关闭 + 听书模式**
- 交付：阅读器 TTS 栏新增定时器（读完本章停 / 10 分钟 / 20 分钟 / 30 分钟）；定时到点温和停止并给一句晚安语（不催促、不警告）
- 延伸：锁屏/息屏时 TTS 继续（`navigator.wakeLock` 或媒体会话元数据），让「听」成为一等体验（B6 最小实现）
- 验收：e2e 定时器按钮存在 + 选中态持久化；单元测试覆盖倒计时取消

**P0-2（A2）书籍详情页**
- 交付：书架卡片点击 → 详情页（大封面 SVG + 适龄标签 + 难度星级 + 简介 + 章节目录 + 「试读第一章」/「开始读」双按钮），而非直奔阅读器
- 设计约束：64px 触摸目标、WCAG AA、无纯黑/白（docs/design-system.md）
- 验收：e2e 详情页元素齐全 + 试读只读首章 + 深链路进入阅读器带正确 startChapter

**P0-3（B1）共读脚手架前移**
- 交付：阅读器内家长可见的「今晚怎么讲」浮层（本页可问什么 + 关键词解释入口），数据来自已有 `QUESTIONS_BY_STAGE`/`HOOKS`/`STAGE_TIPS`，按当前章节内容匹配
- 约束：家长向入口，孩子端默认不显示（避免打断孩子阅读节奏）
- 验收：e2e 家长模式开关 + 浮层内容随章节切换

**P0-4（C1+C2）周报数据正确性**
- 交付：`reports/service.ts` 书名解析增加内容域分支（内容包标题表 / `bookId` 去 `cbf:` 前缀查内容库）；内容阅读时长在收尾时按真实起止计算并计入 `durationSec`
- 验收：单元测试构造内容域 cosession，断言周报出现真实书名 + 分钟数 > 0

**P0-5（C3）续读位置恢复**
- 交付：ReaderScreen 滚动时节流上报 `blockOrder`（块索引）；打开章节时按 `blockOrder` 滚动恢复
- 验收：e2e 读到第 N 块 → 退出 → 重进 → 滚动位置恢复

**P0-6（C4）家长端内容域可见**
- 交付：家长页新增「桃书库」分区：孩子在读/读完的公版书 + 进度 + 屏蔽开关；周报书目含内容域
- 验收：e2e 家长页可见内容域书目 + 屏蔽后孩子端书架消失

**P0-7（C5）TTS 单元测试**
- 交付：`apps/web/src/lib/tts.test.ts`——分句（中英标点、超长无标点兜底）、语音打分排序、单例取消（新 speak 中断旧队列）
- 验收：vitest 覆盖 tts.ts 全部分支

**P0-8（C6）英文内容扩容**
- 交付：Alice / Peter Pan / Grimm 各扩至 ≥3 章，新增至少 1 本英文公版书；每章带原创 SVG 场景
- 约束：RightsInfo 每包必带（pd-70 / pd-us 判据 + 译者留空则不声明翻译权）

**P0-9（A4-最小版）内容域黑名单**
- 交付：家长可在桃书库分区屏蔽单本，孩子端书架/推荐流即时过滤
- 验收：e2e 屏蔽 → 孩子端该书消失

### 4.3 P1 任务卡（验收日前尽力）

- **P1-1（B2）语音搜索**：孩子端书架麦克风按钮 → Web Speech API 语音识别 → 书名/作者模糊匹配 → 结果列表。照顾不识字孩子，落地「孩子真实选书权」
- **P1-2（B6）听书模式**：纯音频播放视图（封面 + 进度 + 定时器），息屏继续播放
- **P1-3（B3）成就文案审查**：按 Scholastic 约束，把「最长连续 N 晚」类 streak 文案改为庆祝「这 N 晚读了什么」，避免 streak 焦虑
- **P1-4（A3 完整版）**：周报加兴趣分布（哪类主题读得最久）+ 内容域分钟数单列

### 4.4 明确不做（本轮淘汰，附理由）

| 淘汰项 | 理由 |
|---|---|
| 积分商城 / 虚拟宠物兑换 | 红线；且 ABCmouse 4.13 星（同段位最低）证明外部奖励反噬内在动机 |
| 打卡对赌 / 0 元返学费 | 红线；微信曾因恶意营销禁朋友圈打卡 |
| 连胜火苗 / 断签惩罚 | 红线；专家结论「唠叨会彻底毁掉阅读动机」 |
| 面向孩子的推送 | 红线（防沉迷） |
| Learn First 式「阅读解锁娱乐」 | 把阅读工具化，与内在动机目标相悖 |
| 看视频解锁时长 | 反面教材 |
| 重内容采购 / 付费课程 | BYOK + 公版库路线已锁定成本结构 |
| 家校共育 / 班级书房 | 渠道机会成立，但不是 4 天内能做的事，留 v3 |

### 5.2 「图文并茂」的现状基线

v2 已有 28 个原创 SVG 场景，e2e 有结构断言（`svg[data-art]` 存在性 + 页脚不遮挡正文几何检查）。本轮要补的是**覆盖密度**：当前仅章节级插图，详情页大封面、空状态、成就墙仍缺图。目标：每个有文字的屏幕都有配套 SVG 场景。

## 6. TTS 升级路径（用户三大需求之一：语音必须拟人化）

### 6.1 现状

- Web Speech API 浏览器端实现：在线神经语音优先（Google 普通话 / Microsoft 晓晓）、分句播放、句间 90ms 停顿、边界事件句级高亮、全局单例
- 打分函数选最优语音，但**受限于设备已安装的语音包**——低配设备/国产浏览器会退回机器人音
- 零单元测试（C5）

### 6.2 调研结论（完整方案见调研记录）

| 方案 | 结论 |
|---|---|
| **Azure 认知服务 F0** | ✅ **首选**：500 万字符/月免费额度（F0 档），XiaomoNeural 单语音多角色对话（覆盖「拟人化」需求），有儿童声，WordBoundary 事件可做**逐词高亮**（对标 Vooks） |
| 阿里云语音 ISI | ✅ 备选：国内延迟低，儿童场景有声模型 |
| edge-tts | ❌ 拒绝：中国大陆 403 + 逆向工程微软未公开接口，合规风险 |
| Google Cloud TTS | ❌ 本机不可达 |

### 6.3 本轮决策

**P0 范围内**：不引入外部 TTS 服务。理由：
1. 引入云端 TTS 需要 API key 出网，与「密钥只在 .env」的红线叠加新的攻击面，且免费额度需绑定信用卡（交付评审阶段不适合）
2. 用户验收在 9-20，4 天内做服务端 TTS + 前端切换 + 降级链，风险高于收益
3. **C5 单元测试 + 打分逻辑加固是本轮的性价比之王**：先保证现有引擎正确可靠

**本轮做**：
- TTS 单元测试（C5）
- 语音质量兜底加强：无神经语音时的 UI 降级提示 + 语速/音高预设（故事模式 = 慢速 + 略高音高）
- **定时关闭**（A1，听书场景核心）
- WordBoundary 逐词高亮的**可选**优化（若浏览器支持 charIndex，已在 tts.ts:253 预埋）

**P2（验收后）**：Azure F0 服务端代理 + 前端语音源切换 + 逐词高亮，作为 v3 的听书基础设施。此时 `.env` 红线方案成熟，可安全接入。

## 8. 风险与诚实声明

1. **视觉层无法自查**：本环境无图像输入能力，所有 UI 成果只能靠结构断言（DOM/几何/对比度计算）保证，像素级美感需人类在 9-20 验收时亲自看。已把「不可证的视觉主张」全部转成「可测的结构断言」。
2. **竞品截图已备好**：`research/shots/` 90 张，含拼图 `montages2/`。若验收时人类觉得视觉不够好，可对照截图逐屏调。
3. **调研信源偏早期**：国内拆解文章 2018–2020 居多，界面结构可能已被当前版本推翻；所有涉及具体界面的条目都标注了年份。
4. **Scholastic 数据为二手转引**（原 PDF 超 10MB 抓取上限），方向可信但精确百分比应在正式物料中回溯原报告。
5. **Azure F0 本轮不接入**：这是权衡而非遗漏，理由见 §6.3。
