# 独立家长 PIN 认证与迁移

日期：2026-10-15。独立家长 PIN 已部署；按用户明确授权，生产 1 个旧家庭已完成迁移，未设置 PIN 的家庭剩余 0。实际记录和新 PIN 查看方式见第 6 节。

## 1. 登录和恢复规则

- 新家庭：创建时必须设置并确认 6–12 位数字家长 PIN，服务端验证格式后创建家庭及家长会话。
- 孩子：使用家庭码加入，不需要、不发送 PIN；不能请求家长接口。
- 家长新设备：家庭码和 PIN 都正确后才创建家长会话。仅改变请求中的 `role`、附上历史 `parentCode` 或解答前端乘法题，都不能取得家长权限。乘法题入口已移除。
- 更改 PIN：设置页输入当前 PIN、新 PIN 及确认。服务端验证当前 PIN 后更新凭据版本；当前设备取得新令牌，其他家长会话撤销，孩子会话保留。
- 旧家庭迁移、遗忘 PIN、唯一家长设备丢失：由拥有服务主机与服务配置访问权的管理员交互恢复。家庭码、设备 ID、旧家长令牌不能证明独立的家长身份，不能用来无条件抢先设置 PIN。

先前所有家长令牌都能仅凭家庭码取得，无法从历史角色或设备 ID 自动辨认真正家长。新守卫拒绝没有匹配 PIN 凭据版本的家长令牌，因此旧家庭必须由管理员完成迁移。不会给真实家庭设置通用默认 PIN。孩子的旧令牌和阅读数据不因此失效。

## 2. 服务端边界

`Family` 新增 `parentPinHash`、`parentPinVersion`、`parentPinAttempts`、`parentPinWindowStart`。哈希使用随机 16 字节盐、scrypt（N=32768、r=8、p=1），输入先经独立用途域的服务端密钥 HMAC 处理；不保存明文 PIN。服务端密钥由现有主密钥派生，不在数据库内保存。更换主密钥后，需要使用恢复工具重新设置 PIN，不能沿用原哈希。

每家庭每 15 分钟最多 5 次未成功的验证尝试；名额在运行哈希前通过数据库条件更新原子占用，成功验证清零。限制跨 IP、应用重启及并发请求持续生效，超时后恢复。登录和改 PIN 共用该限额，孩子登录不受 PIN 限额影响；现有 IP 限流继续生效。攻击者可触发短暂家长登录拒绝，但不能由此取得家长权限，已登录家长仍可管理家庭。

每次家长 API 或私有媒体请求都检查当前凭据版本，绕过孩子端的会话缓存；PIN 变更/主机恢复后，旧家长令牌和旧媒体票据立即失效。媒体票据携带角色及凭据版本，不能用于 API 登录。孩子会话继续采用原有最多 30 秒缓存和主动撤销逐出规则。

错误 PIN 在设备额度处理之前拒绝，不能创建设备或踢出其他设备。孩子加入只能替换旧孩子会话，不能挤出家长；全部设备额度均由家长占用时，孩子加入返回 429，需由家长腾位。已验证 PIN 的家长仍能在满员时替换旧会话进入，避免唯一管理入口被额度锁死。

PIN 和哈希不回显、不写入事件日志、不随家庭记录导出，前端输入使用密码框，仅保留在当前组件内存。登录请求不附带旧会话，避免旧令牌阻断重新登录。

## 3. 通用发布与迁移顺序

本节供今后发布或恢复参考；本次生产发布已执行对应步骤，实际结果见第 6 节，无需用户再次迁移。

1. 按现有生产流程取得一致性备份，核对数据库、媒体及服务配置的恢复能力。管理员确认目标家庭归属和 PIN 的交付对象，不能根据前端声称的家长角色自动批准。
2. 停止目标 API 服务，更新后端、前端及 Prisma 模型。不要让新登录页面与旧的无 PIN 后端混用，也不要让旧 API 在迁移期间继续签发家长令牌。
3. 在配置好目标服务环境的 `apps/server` 目录运行：

   ```powershell
   npx --no-install prisma migrate deploy
   npx --no-install prisma generate
   ```

   迁移为追加四列，不删除家庭和阅读记录。Windows 生成时需要停止使用该 checkout 的 API 进程以释放 Prisma DLL；不要关闭其他项目或其他 checkout 的服务。

4. 对每个需要迁移的旧家庭，在配置好目标数据库与主密钥的服务目录打开交互终端运行：

   ```powershell
   npm run parent-pin:recover
   ```

   或在项目根目录运行 `npm run parent-pin:recover -w @taoread/server`。工具依次交互读取家庭码、新 PIN、再次输入和 `RESET` 确认，全部不回显。不要把 PIN 放到命令行、脚本、环境变量、工单或日志。成功后全部旧家长会话撤销，孩子会话和阅读记录保留。没有图形终端/TTY 时拒绝运行。

5. 按项目构建流程生成前端，启动配套的新 API。由家长使用家庭码和新 PIN 登录；旧版本会话重新登录提示会说明 PIN 要求。新家庭必须自行设置 PIN。
6. 生产验收至少检查：仅家庭码申请家长失败；正确 PIN 家长可管理；错误 PIN 不产生设备；孩子管理接口拒绝；改 PIN 后旧设备及旧媒体票据失效；孩子阅读和进度保留；唯一家长丢失后可从主机恢复。

本机测试中的演示假 PIN 仅供隔离演示库。已有演示库也不会自动写入公开默认 PIN，需要用同一恢复工具迁移，或由操作者明确重建演示库。

## 4. 回滚与恢复

四列迁移可以保留，不需要为回滚页面删除凭据字段。不得回滚到“家庭码 + 自选 role”即可取得家长身份的旧后端；发生上线问题时保持安全版本或暂停家长管理入口，保留孩子只读能力。恢复旧数据库备份会同时恢复旧凭据状态，应再次运行 PIN 恢复并撤销旧家长会话，再开放管理入口。
