# 103 — 桃阅读「真安卓应用」开发分析（2026-11-05）

前序：docs/67（客户端方案研究）、docs/68（实施计划，M1 已上线）、docs/74（APK 冷启动实测）。
性质：分析文档（非实施 spec）；实施须另立 spec/plan 走设计审批。

## 0. 结论速览

**「真安卓」有三档定义，先拍板再动工：**

| 档位 | 形态 | 一句话 |
|---|---|---|
| A 远程壳（现状） | Capacitor + server.url 指生产站 | APK 只是浏览器皮；每次冷启=整站公网加载 |
| B 本地壳+原生增强（推荐） | web dist 打进 APK + 原生模块 | 首启后断网可开、后台朗读/播放交给原生 |
| C Kotlin+Compose 全原生 | 全部 UI 原生渲染 | 最「真」，成本最高，长期双源码 |

**推荐路线 B**（与 docs/67 的 M2 规划一致）：保留 WebView 渲染资产（拼音 ruby/分页/字级高亮/
CSS 排版是三年资产），把「原生才做得好」的四件事交给原生：后台朗读、推送、离线内容、启动速度。

## 1. 环境事实（决定可行性的物理约束）

- **无 GMS 设备占比**：华为全系无 GMS；小米/OPPO/vivo 海外版受限，国行正常带 GMS 但后台杀进程激进。
  FCM 推送在无 GMS 设备**不工作**，在有 GMS 设备被激进省电策略抑制——推送方案必须按「FCM 不可依赖」设计。
- **应用市场上架硬门槛**（国内）：软件著作权（代理 ~1-2 月/官方通道更久）、ICP 备案域名、
  儿童隐私合规材料、每家市场单独审核。taostudioai.com 是否已备案：**待核实**（未备案则只能侧载）。
- **WebView 碎片化**：Android System WebView 依赖 Google/厂商更新；无 GMS 设备 WebView 可能常年旧版
  （对标 web 端 legacy 双包的存在理由）。es2018+modernTargets 地板不变。
- **侧载生态**：dl.taostudioai.com 通道已跑通（versionCode/Name/manifest 三件套红线已固化）。

## 2. 现状基线：远程壳 APK 的能力与缺口

**能力（不要推翻的资产）**：
- Capacitor 远程壳已发布 0.1.3/0.1.4/0.1.5，dl 通道自更新已闭环实测（v0.1.2 起 15s 超时防挂起）
- web 端 api.ts 的 absolutizeMedia 已根修 APK 媒体裂图/无声（壳 origin=localhost 场景）
- 版本三件套红线（versionCode/versionName/RELEASE.md 段）与 .env.dist 发布凭据流已固化（publish-mobile.mjs）

**缺口（「不真」的根源，docs/74 实测数据）**：
1. 冷启动=整站公网加载：弱网实测 ready 7,211-11,667ms；断网=白屏（F39 产品决策：不支持离线）
2. 后台朗读被杀：WebView Audio 不持前台服务，息屏/切走几分钟即断，孩子听故事场景硬伤
3. 无推送：每日阅读提醒（F35 已有服务端+web 端实现）在 APK 内无法触达
4. WebView 版本随设备碎片化：旧 WebView 上 modern 包兼容风险（legacy 双包兜底但体积翻倍）

## 3. 关键技术事项盘点（按域）

### 3.1 渲染层（路线 B 保留 WebView；路线 C 全重写）
- 必须保真的三件资产：拼音 ruby 注音、columns 分页（双页横滑）、朗读字级高亮（box-shadow 光晕零布局方案）
- 路线 C 若做：CJK 排版/ruby/分页/高亮四件全要原生重写（Compose 无原生 ruby，需自绘），
  这是全项目最贵的单一资产，估计占全原生成本 40%+
- 星空课堂 three.js（523KB chunk）：WebView WebGL 可跑；原生替代（filament/SceneView）=重做交互

### 3.2 朗读/音频（原生价值最高的单点）
- 现状痛点：息屏断播、锁屏无控制、蓝牙耳机按钮无响应、音频焦点冲突（来电话不停播）
- 原生方案：Media3/ExoPlayer + MediaSessionService（前台服务）+ 音频焦点管理 + 预加载队列
- web↔native 桥：Capacitor plugin 暴露 play/pause/seek/onSegment 回调；web 朗读编排逻辑不变
- 预生成 mp3（17,872 段全 CDN 化）直接喂 ExoPlayer；实时合成兜底（SSE）保持现有 API

### 3.3 离线与下载（产品决策点：F39 是否翻案）
- F39「不支持离线」是远程壳时代的决策——「真应用」最大卖点恰是离线；**需要用户拍板翻案与否**
- 若翻案：R2 CDN+sha256 校验已备；本地库 = SQLite（房间）或文件+manifest；下载管理（断点/校验/配额）
- 书架下发 thumb 档（35KB/张）+ 章节档（800w）已有分档，离线包按「书」为单位打包下载

### 3.4 推送/提醒（无 GMS 现实下）
- 方案对比：FCM（仅 GMS 设备）／厂商通道（Mi/HW/HO/vivo 各自 SDK+开发者账号+审核）／
  聚合推送（极光/个推，免费档+隐私合规审查）／自建长连接（成本高，否）／无推送改本地提醒（AlarmManager+通知，零依赖）
- 家庭自用规模（1 个家庭码）下：**本地提醒（AlarmManager 定时通知）性价比最高**，厂商通道为后续选项

### 3.5 分发/更新渠道（保持侧载为主，市场上架为可选后期项）
- 现有 dl.taostudioai.com 侧载通道+自更新闭环已实测（15s 超时回落）；继续作为主渠道
- 应用市场上架（可选后期）：软著/ICP/儿童合规三证材料清单见 §1，按「用户是否想上市场」拍板
- 应用内热更 vs 整包更新：远程壳时代整包更新频率低（壳稳定）；路线 B 后壳内 web 资产更新
  =「应用内自更新 web 资产」（下载新 dist 包+校验+原子替换）可作为 M2 可选增强，非首期

### 3.6 签名/版本/凭据（已有红线沿用）
- keystore 单一长期签名（taoread-release.keystore 在库——**注：私钥入库是家庭自用产品已接受的取舍**，若未来上市场必须迁出并轮换）
- versionCode 单调递增红线；RELEASE.md 段冲突坑（publish-mobile.mjs 已处理）

## 4. 内容与媒体层（全路线共用，已基本就绪）

- API 全复用：REST（家庭码/device session）+ SSE（实时合成兜底）；CORS/OPTIONS maxAge 600s 已修
- CDN 全复用：17,872 段音频+图档已 100% CDN 化（docs/102）；媒体票据 4h 桶+max-age=14400
- 需原生等价实现的一件事：媒体 URL 的 absolutizeMedia（现 web api.ts 内）→ native OkHttp interceptor
  （或继续用 WebView 内的 web 逻辑，路线 B 下零成本）
- 存储红线：家庭媒体缓存票据绑定精确路径（10-20 教训：前端换 URL 兜底必 401——回退 URL 必须服务端成对签票）

## 5. 推荐路线分期（每期独立可验收）

| 期 | 内容 | 量级 | 验收门 |
|---|---|---|---|
| M2a 本地壳 | server.url 移除+内置 dist 成为主内容+版本内嵌 API 基址+首启同步检查 | 1-2 天 | 断网冷启可进登录/书架（离线壳级） |
| M2b 原生朗读 | Media3 后台播放+锁屏控制+音频焦点+耳机按钮 | 2-4 天 | 息屏听完整本故事不断播；锁屏/通知栏可控制 |
| M2c 离线内容 | 书级下载+本地索引+配额管理（需 F39 翻案拍板） | 3-5 天 | 飞行模式读已下载书+听已下载音频 |
| M2d 提醒 | AlarmManager 每日阅读提醒+通知（无 GMS 依赖） | 1-2 天 | 杀进程后次日仍按时提醒 |
| M2e 市场材料 | 软著/ICP 核实/儿童合规包 | 人工项 | 材料齐备可提交 |

## 6. 风险登记

| 风险 | 缓解 |
|---|---|
| 路线 B 的 WebView 依旧受设备 WebView 版本影响 | 保留 legacy 双包；真机矩阵覆盖家里 2 台设备即可（自用产品） |
| 双端行为漂移（web 更新快、壳更新慢） | 远程壳→本地壳切换后：核心流（书架/阅读/朗读）e2e 门 + 每期真机门 |
| 离线内容与票据 URL 过期（4h 桶） | 离线包落盘=免票据（本地文件）；在线播放才走票据 |
| F39 翻案后服务端配额/清理 | 下载配额按家庭（沿用 genDailyLimit 思路）+ LRU 清理 |
| 上市场上架审核周期不可控 | 侧载为主渠道不动摇；市场作为可选后期项 |
