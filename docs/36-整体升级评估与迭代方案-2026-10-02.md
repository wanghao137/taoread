# 桃阅读整体升级评估与迭代方案

日期：2026-10-02。评估基线：本地 HEAD `37c8a34`，包含 `cb8e21c` 性能升级。本文仅交付评估和实施方案，不代表开始改造、上线或改变已有产品决策。

补充评估：[UI / UX / UE 专项评估与升级方案](37-UI-UX-UE专项评估与升级方案-2026-10-02.md)。后续已通过 Playwright CLI 完成线上公开登录页及隔离演示环境的手机、平板、桌面抽样检查；本文件原评估阶段的浏览器超时记录保留，新的页面证据与具体界面整改以专项文档为准。生产家庭完整流程和真 Safari 音频仍未验证。

## 1. 结论与评估边界

桃阅读已有相当完整的功能基础。真正需要升级的，是把“功能存在”转变为“承诺准确、内容可信、流程连贯、数据可靠、长期可运营”。建议定位为：**面向 3–12 岁家庭的轻量阅读与亲子共读空间，以可信内容、顺畅阅读和可回看的家庭阅读记忆为核心。**

升级主线依次为：可信度与权限 → 阅读闭环 → 内容治理 → 多书源体验 → 家庭回顾 → 性能与运营。不要以书籍数量、功能数量、在线时长作为升级成功的主要指标。

证据范围：阅读 README、历次方案与交付记录；检查路由、核心前后端服务、阅读器、内容包与权利结构、Prisma 模型、SW、测试配置和 CI。初始 Git 工作区干净。线上浏览器访问两次分别超时，未成功完成页面检查；本轮没有登录生产家庭、调用付费生成接口、修改数据库、运行会写账本的业务流程，也没有重跑完整质量门。

因此本文区分：

- **代码确认**：可以直接从当前实现推导的行为与边界。
- **历史记录**：旧报告所载数字，只作背景，不称为本次实测。
- **待验证**：真实设备体验、生产性能、实际内容覆盖、备份可恢复性及用户需求，必须在对应实施阶段补证。

docs/34 的“34 项落地”不能视作全部原始验收目标满足：文末明确记录跟读录音 UI、UI 音效未落地，难度与小测采用了替代实现。docs/35 已包含执行记录，压缩、R2 变体、目录缓存、ETag、预取、拆包等不能再次列成从零开发任务。

## 2. 从第一性原理定义产品

### 2.1 用户真正完成什么

孩子需要找到愿意读、能参与的内容，随时知道怎么开始和怎么继续；家长需要低准备成本地陪伴、解释和交流；家庭需要留下真实而温暖的记忆。阅读工具的价值来自阅读发生，而不是工具使用时长。

三条主流程：

1. 自主阅读：选人 → 找到适合的书 → 读或听 → 恢复位置 → 自愿结束 → 以后继续。
2. 亲子共读：选书 → 家长获得简短且贴合原文的提示 → 一起阅读 → 可选回顾 → 留下记忆。
3. 屏外阅读：纸质书或微信读书 → 极少操作开始/记录 → 在外部阅读 → 回来收尾；不以缺少滚动数据判定没读。

### 2.2 不可混同的概念

| 概念 | 可以观察的信号 | 不能直接推出的结论 |
|---|---|---|
| 读过 | 打开、恢复进度、用户确认 | 读懂或掌握 |
| 听过 | 音频播放区间 | 独立识字能力 |
| 阅读投入 | 前台可见、交互与播放、用户确认 | 全程专注或学习效果 |
| 理解 | 针对原文的复述、因果交流、经审核问题 | 选中了出现过的词就读懂 |
| 难度 | 文本长度、词汇句法、题材、用户反馈 | 章节短就适合某个孩子 |
| 适龄 | 编辑建议和题材审查 | 同年龄孩子能力一致 |
| 家长门 | 防止孩子误触管理入口 | 身份认证和资源授权 |

### 2.3 产品约束与取舍

保留免费、无广告、无积分兑换、无断签惩罚的方向；尊重不依赖真实儿童身份的原则。自然拼读继续维持草稿/内测定位，口音与教学内容未定稿前不宣称系统课程。现有“单家庭码”是代码注释记载的历史产品决策：提出安全升级备选，不在方案阶段擅自恢复家长码。

公共静态内容适合边缘分发；家庭私有书、录音、金句和凭据不能进入公开媒体桶。家庭 Windows 主机、SQLite 与 Tunnel 可以继续承载小规模使用，但可用性上限必须以真实并发和故障数据判断，不能预设必须迁云或重写架构。

线上移动端视觉、真实 iPad Safari 音频/锁屏、图片失败回退、跨设备进度冲突、私有媒体鉴权与注销清理、版权展示完整性、备份加密与恢复、供应商超时与账单上限、实际首屏性能和用户使用意愿。它们是验证任务，不在没有证据时列为已发生缺陷。

## 4. 分领域升级设计

### A. 产品定位、首次使用与信息架构

目标：新家庭无需读说明就完成第一次有价值的阅读。

- 登录前用一句话说明“选好书、一起读、留下记忆”；提供无家庭私人数据的公开示例，避免示例变成生产共享账号。
- 创建家庭仅收必要信息，清晰说明年龄段用于内容建议；昵称提示避免真实姓名。
- 创建成功给家长凭据/恢复说明与设备加入方式，不把儿童入口与危险管理混在一起。
- 孩子保留“今天 / 找故事 / 我的”；今天突出继续读、少量推荐、纸书和家庭书快捷入口。
- 家长今天突出“今晚读什么、怎么陪、最近发生了什么”；内容管理、回顾、设置各司其职。
- 桌面/平板显示更多上下文，小屏只保留当前任务；不为品牌改版重做整个视觉系统。

验收：用无项目背景的家长完成首次任务；目标为 2 分钟内进入第一篇内容，最多一次解释。指标属于待验证目标，不是当前成绩。

### B. 找书、推荐与分龄

- 拆开年龄建议、篇幅、语言、题材、阅读方式和编辑难度；“适合共读”不等于“可独立阅读”。
- 第一阶段沿用轻量算法，但解释推荐理由：“上次没读完”“你收藏过同类”“短篇，适合今晚”。不要生成没有证据的个性化判断。
- 时间型合集按章节可读时长筛选，并区分家长朗读、孩子阅读和音频长度估计；缺少可靠估计时不做精确承诺。
- 合集支持编辑固定成员、排序、推荐原因、适龄与下架过滤。先精选 6–8 个真实主题，不继续增加相似分类壳。
- 搜索先确保书名、作者、章节结果定位明确；拼音/同义词扩展以真实查询需求决定。
- 没搜到、全部屏蔽、没有适龄书、离线等状态分别表达；不要都呈现“空书架”。

验收：列表和详情标签一致；屏蔽其他书不改变一本书的编辑难度；所有带“十分钟”的成员满足约定标准；随机推荐不突破屏蔽和年龄边界。

### C. 阅读器与音频

优先把阅读变成可靠的主干流程。

1. 控件分层：一级只有返回、目录、听读、阅读设置；跳段、音色、倍速、定时和共读提示放二级。避免儿童屏幕同时出现大量小按钮。
2. 两种阅读器采用相同主题、排版、音频状态、错误提示和恢复交互；纸书/微信读书保持屏外流程，不能硬套页面进度。
3. 书签采用家庭+孩子+书源+书籍+版本归属；初期安全的本地隔离即可，跨设备服务端同步作为后续明确能力。旧本地书签没有所有者证据，不能静默分配给某个孩子。
4. 进度采用稳定章节/块锚点与内容版本；更新文本后定位失败要有明确回退与提示。优先保护既有进度，不用全量重新 seed 破坏锚点。
5. 音频统一 idle/loading/playing/paused/error/ended 状态，切书、换人、退出登录必须停止和清理。
6. 区分加载慢、无可用音色、供应商失败、浏览器限制、网络中断；降级说明自然简短，不能把不同引擎的声音切换伪装成完全一致。
7. 图片维持变体优先，补足移动端实际清晰度、放大与多级回退验证；章节预取遵守省流量与弱网条件。
8. 跟读录音采用独立可选试点：用户手势授权、本地回放、明确删除，不做识字或发音分数；默认不上传。

验收矩阵：iPhone/iPad Safari、Android Chrome、桌面 Chromium；前后台切换、锁屏、暂停恢复、断网、503、连续翻章、换孩子、隐私存储限制。浏览器不能支持的锁屏/后台能力明确说明，不作跨平台绝对承诺。

### D. 共读与收尾

- 开始以选定书为依据，已存在另一会话时保留当前冲突选择，不偷偷关闭旧记录。
- 共读脚手架从模板泛问升级为章内证据：一句提示、一个开放问题、一个生活关联，展示可选答案依据给家长；低龄可指图/表达，高龄可解释与讨论。
- 收尾默认简短：今天先到这里 → 可选心情/一句话；不强制答题、金句或成就分享。
- 小测先移除“掌握/读懂”结论。后续精选书建立审核过的情节、因果、人物选择题；错误不惩罚，不影响继续阅读。
- 成就只纪念真实发生的阅读，安静模式轻提示；共享卡预览后由家长主动导出。

验收：不回答任何问题仍可正常结束；重复结束只记一笔；脚手架与对应章节有人工可追溯依据；空内容/单章/英文短篇不会拼凑伪题。

### E. 内容质量与权利治理

把内容从代码包升级为可审核资产，而不是先扩书库。

每本书维护来源作品、章节来源、作者/译者、语言、完整/节选/改编/原创、加工说明、版本、编辑建议、阅读方式、题材提示、来源链接、权利依据与授权版本。先允许字段存在审核清单中，验证工作流后再迁数据库。

- 全库结构审计：缺章节、空块、重复正文、异常短章、错字候选、拼音对齐、图文场景不符、媒体缺失与台账不完整。
- 先抽样每种语言、来源、年龄、内容类型；高风险样本优先：经典原文、现代译文、科学解释、恐惧/暴力题材、开放授权材料。
- 人工审核优先精选 20–30 本作为推荐核心，确保文字、读音、图片、共读提示形成一套可交付体验；实际人工工作量随章数重估。
- 原文与注释分离，不把括注混进“原文不改”正文。节选、改写、AI 原创及新生成插画如实标明。
- 作品、译文、插画各自有权利边界；公开许可要保留要求的作者、许可证和加工说明，不能只存一个泛化 `source` 字符串。
- 草稿 → 校验 → 审核 → 发布 → 下架；下架从搜索、推荐、合集移除，但保存阅读账本与必要的历史元数据。
- 拼音、释义、TTS 多音字建例外词表与人工抽听；科学内容标注编辑依据，不宣称经科学审定。

验收：精选内容 100% 有逐章审核清单与明确加工方式；抽样问题形成批次追踪；未审核内容不包装成“精选”。授权事实不明时先退出推荐并待核实，不能由技术规则自动宣告合法。

### F. 家庭数据、报告与时长

- 明确区分阅读进度、共读会话、听读区间、用户确认完成，统一书源引用，但保留各自的数据来源。
- 会话跨度与可确认的活跃时长分开显示；浏览器前台/播放只是估计，纸书由家长确认。既有记录保留原口径，不用新算法篡改旧数值。
- 完成事件记录完成时间和当时内容版本；历史周报基于当时事件，不能被当前 `finished` 状态反向影响。
- 没结束的会话、跨午夜/跨周、重新读完同一本、纸书完成、家庭导入书的统计给出明确规则与样例。
- 周报按孩子展开，统一公共书划线与共读金句的回顾入口；家庭书标题由家庭归属解析，不能暴露内部引用 id。
- 回顾以书、对话和记忆为主，数字为辅；不输出“阅读能力提高 X%”等无依据结论。
- 数据导出带版本与来源，注销前允许导出；分享卡避免家庭凭据、真实儿童身份与私人书正文。

验收：给定一组固定跨周、多孩子、多书源样例，今天/历史/周报/导出一致；查看历史不会因为今天修改进度而改变历史完成事实。

### G. 身份、隐私与运营权限

近期必须隔离普通家长与平台运营。平台路由不能只靠“隐藏导航”和 parent role；优先使用已有可信的部署侧认证/运维访问策略，另设平台角色应有显式配置和审计，不自动授予现有家庭。

家长授权存在两个实施分支：

- **仅可信家庭便利模式**：保留单码，但明确其拥有家庭管理权限；危险操作二次确认，凭据可轮换，会话可撤销。它不是独立家长身份隔离。
- **公众多家庭模式（建议）**：儿童加入与家长管理权限分离，可采用创建时绑定管理设备、家长 PIN/管理凭据、家长批准新管理设备。具体方式在迁移设计时定稿，现有家庭不得无恢复通道地被锁出。

其他工作：会话过期清理与设备去重、登录失败限流、家庭码轮换、操作审计；CSP 从 report-only 过渡到强制前先收集真实违规与测试；私有媒体能力令牌的撤销/失效、注销后的 DB/文件/缓存清理做专项复核。

验收：直接调用 API 也不能跨家庭、不能用儿童权限执行管理动作、普通家长不能看平台聚合；迁移后旧家长有明确可恢复路径。隐私政策与真正处理的数据一致，麦克风使用单独请求授权。

### H. 性能、离线、工程与运维

docs/35 成果作为基线保留，先复测后优化。目标端到端时间，而不是仅比较服务端函数耗时。

- 性能基线分冷/热缓存、首次/回访、移动/桌面、正常/弱网；记录 LCP、CLS、INP、API p50/p95、传输字节、图片失败率、音频首响与卡顿。
- 静态书目与用户态逐步拆分缓存；私有响应保持隔离，ETag 必须覆盖内容变化和用户动态状态。
- 预取尊重 saveData/低速网络；首屏优先必要资源，不为“切端零等待”无条件加载另一个端的全部代码。
- 性能门从“有 gzip、DTO 有变体字段”扩展到真实图片 URL/体积、首屏关键资源、重复请求、缓存失效及弱网降级。
- 离线先准确说明当前限制，再试点“用户主动保存公共书”：离线导航、版本、容量、删除、配额不足和内容下架规则同时设计。初期不缓存家庭私有书和音频。
- 备份已有 `apps/server/scripts/backup-to-r2.mjs` 与调度入口，下一步检查实际运行和加密/留存，做独立恢复演练；有上传成功日志不等于可恢复。
- 当前备份实现保留最近 3 个 DB 快照、媒体按本地真值同步并删除远端孤儿，增量水位不区分备份目标。这是镜像式同步的一部分，不能单独抵御误删传播；应另设可回溯保留窗口/版本策略，切目标强制全量并绑定目标身份，验证历史 DB 与媒体可组成同一恢复点。
- 观察 API 与 Tunnel 两段健康、磁盘空间、DB 锁等待、备份新鲜度、媒体一致性和供应商预算；慢请求日志不能单独推导总体 p95。
- 发布采用版本化产物与数据库迁移清单；界面更新与旧 chunk 生存期协调，解决长时间打开客户端更新场景。
- 继续使用现有 verify/CI，不另造重复测试框架。提取两套阅读器共享服务按行为边界进行，不为“重构完成”集中重写。

验收：独立目录恢复成功，媒体与数据库一致；备份建议目标 RPO≤24h、RTO≤2h，最终以演练结果确认；每月存储、API 调用与生成费用有上限和处置策略。

## 6. 推荐发布节奏

### R0：可信基线，约 1–2 周

T01–T04、T15 的必要部分；修正错误教育反馈、运营数据权限和书签归属。输出明确的部署模式/家长授权备选与内容风险清单。门槛：已确认 P0 有修复证据；尚未验证项仍显式列出。

### R1：阅读稳定版，约 2–3 周

T05–T07 的核心子集，完成家长权限方案、两类阅读器核心一致、弱网/音频恢复与可靠账本。门槛：多孩多书源、跨设备、跨周和关键真实设备矩阵通过；无未解决的数据丢失/错误归属。

### R2：精选内容与家庭回顾版，约 2–3 周

T08–T11，先少量高质量内容；提高推荐、共读提示与家庭回顾价值。门槛：精选内容逐章审核，家长任务验证，统计对账通过。内容审查与工程可在资源允许时交错推进。

### R3：可持续运行版，约 1–2 周

T12–T15 的剩余必要项；离线和录音按试点收益决定是否上线。门槛：恢复演练通过、费用有边界、真实性能达标、更新兼容验证完成。

上面的阶段窗口是各阶段核心子集的发布安排，不包含全部可选增强。全任务包预计 10–17 周单人工程投入，依人员、编辑支持和真实设备问题调整；可以先交付约 4–6 周的 R0+R1 核心版本，不必等所有增强项才获得价值。时间与人日不可混为同一承诺。

## 7. 验收体系

### 7.1 产品指标

- 首次阅读成功率：有明确开始动作且内容展示/音频实际起播的家庭数 ÷ 尝试家庭数。
- 续读恢复成功率：重进后位置正确且可继续的次数 ÷ 有历史进度的续读尝试。
- 共读提示有用性：家长完成真实任务后反馈是否降低准备负担，先定性验证。
- 内容问题率：已确认文本/读音/图文问题 ÷ 审核样本；同时保留绝对数与类型，防止小样本百分比误导。
- 统计可信度：固定样例账本、界面、周报、导出一致；历史完成事实稳定。

7/28 天回访可以观察，但不能据此要求孩子打卡。先补充“是否愿意继续”“是否增加家长负担”的小样本访谈，访谈结果标为方向性信息，不外推整体市场。

### 7.2 建议技术预算

| 指标 | 初始目标 | 验证条件 |
|---|---|---|
| LCP | p75≤2.5s；弱网另设基线 | 明确设备、网络、冷/热缓存；先测后定预算 |
| CLS / INP | ≤0.1 / p75≤200ms | 浏览器轨迹与真实任务；小样本仅作实验结果 |
| 续读恢复 | 核心矩阵 100% 正确 | 刷新/换设备/内容版本/冲突场景 |
| 热路径 API | 建议 p95≤300ms | 本机与外网分开、完整请求样本，不只慢日志 |
| 音频首响 | 建议缓存≤2s、实时≤5s | 供应商/浏览器引擎分开，不作未测承诺 |
| 书目传输 | 不超过 docs/35 历史 40KB 档预算 | 书量变化后重设；实测压缩传输字节 |
| 私有数据隔离 | 负向权限矩阵全部通过 | 跨家庭、跨孩子约定、撤销/注销/缓存 |
| 备份 | RPO≤24h、RTO≤2h | 独立恢复演练与实际调度记录 |

### 7.3 必须覆盖的验证

现有 `npm run verify`、前端生产构建、隔离 E2E；增加权限、内容版本、跨周账本、共享设备和缓存失效专项。业务状态测试使用专属数据库和空闲端口，不接入真实供应商或复用生产家庭。

真实浏览器覆盖 360/390 手机、768/1024 平板与桌面，以及至少一台实际使用的旧 iPad。检查键盘、读屏主路径、焦点返回、触控目标、动态字号、安静模式与错误提示。自动化模拟不能替代真 Safari 音频实测。

## 8. 迁移、发布与回退

- 先加可兼容字段，再迁读写；数据迁移 dry-run 输出数量、异常与对账，不打印私人正文/令牌。
- 旧账本带 `legacy` 口径，不把推算出的活跃时长当历史事实；无法确定的旧完成时间保持未知。
- 公共内容版本更新提供锚点映射；未能映射时恢复到最近章节并说明，不清空整本进度。
- 旧本地书签仅提供用户认领/导出选项，不自动分配给当前孩子。
- 公共/家庭媒体分离策略继续保留；恢复环境与生产隔离，密钥安全管理与备份权限单独验证。
- 功能按独立开关发布；先可信度修复，再阅读器，再账本与内容，避免同时变更所有主流程。
- 发布前备份并验证恢复；数据库字段不立即删除，前端回退与数据回退分别制定。迁移失败不能用旧版本硬读不兼容结构。
- 提交、推送、部署、生成付费资产及外部触达都须另有用户明确请求；本文不自动授权这些操作。

## 9. 本轮不宜投入的方向

暂不建设开放式儿童 AI 聊天、自动能力评级、声音克隆、广告/积分商城、大规模内容生成、全面微服务化或强制迁数据库。真人声音与系统课应有独立内容/成本/授权论证；自然拼读等待口音与教学标准定稿。UI 音效优先级低于朗读、弱网和文本质量。

这些方向不是永久禁止，而是当前缺少足够需求、质量和成本证据，不应挤占核心升级。

## 10. 执行前需定稿的少量产品决策

1. 服务范围：自家/可信邀请家庭，还是公开多家庭？决定家长授权方案与运营隔离强度。
2. 主场景排序：自主阅读、亲子共读、睡前听读哪个优先？推荐默认兼顾自主阅读与亲子共读，听读为辅助。
3. 现实资源：每月可接受费用、实际使用设备、是否有人工编辑支持？决定媒体/录音/内容精选节奏。

这些问题不妨碍先执行证据充分的可信度修复，但涉及产品模式改变的实现必须先定稿。方案当前推荐从 R0 开始，不重复上次性能改造，也不先重绘全站。
