## 工程发布和验证

本轮的源码检查、隔离浏览器与发布证据保存在 `output/phonics-release-20261019`。构建必须从精确提交的隔离源码生成，避免将用户另行进行的诗词、图片、桌面及移动端改动混入本次提交或生产。

发布顺序：精确暂存自然拼读文件 → 检查提交范围 → 提交与推送 → 精确提交构建 → 获取一致备份互斥 → 停写、离机恢复点及下载恢复校验 → 生产 fast-forward → Prisma generate / migrate deploy → 安装固定前端构建 → 重启 → 源站与公网校验。未满足前一步则中止，不冒充已部署。

部署前实测：服务端类型检查、前端现代与 legacy 构建、触点检查通过；相关服务端用例按文件/用例名取最新结果共 83 项通过（初次76项有1项WAV夹具扩展名错误，显式修复后内容与旧版内容24项复测通过）。课堂浏览器4/4通过。隔离源码用 UTF-8 解包，1227个归档文件逐字节一致，隔离前端构建通过。

第一次推送的 CI 在既有 Worker 的9个 no-undef 报错处中止。71 中将 `workers/dist-origin`、`workers/dist-proxy` 称为“生成产物”不准确：它们是受跟踪的运行源码。此次为这两个目录补充已有 Cloudflare 平台 globals 作用域，未排除文件或禁用规则；本地完整 `npm run lint` 已通过。CI 后续状态须以新提交的实际运行记录为准。

配置 `TAO_PHONICS_ROLLOUT` 缺省为 off；新版家庭开关缺省 false。正式媒体还同时要求通过审校的内容哈希、数据库 published 版本、家庭开启与会话授权。即使上传了候选文件，也不能使未审课程变成可用。此次不执行 publish/set-default，不伪造 hash-bound acceptance receipt。

回退优先保持总开关 off；保留两次增量迁移，不删除学习数据。生产数据的恢复必须使用一致备份及下载核验文件，不能用开发库覆盖。若需回退旧代码，必须先确认没有 v2 尝试；已有 v2 尝试时须保留 protocolVersion 过滤与媒体拒绝逻辑。
