# docs/108 RTT 收口轮 — 2026-11-07

前提：docs/107 已根治封面传输与重复拉取。本轮方法论=先测后改：在 localhost（传输无关）
量 payload/SSE 组装真值，用「字节 vs RTT」的量尺重排候选——字节已非瓶颈（章节 JSON 仅
1.4-4.9KB gzip），**剩下全部是隧道往返次数（RTT）问题**。

## 1. 测量定案

| 候选 | 实测 | 判决 |
|---|---|---|
| 章节正文 ETag/304 | 章节 JSON 1.4-4.9KB gz；10min 内存缓存+下一章预取已在 | **否决**（字节非瓶颈） |
| TTS 预热端点 | 全缓存章节 SSE 服务端总耗时 720ms（传输无关） | **否决**（组装便宜，省 1 RTT 不值新端点+失效风险） |
| 书架客户端条件请求 | 服务端已有 ETag + max-age=30 HTTP 缓存；W-2 缓存在前 | **否决**（YAGNI） |
| 浏览器引擎音频段间预加载 | 单 Audio 按需赋 src，段间等网络（原生 ExoPlayer 链式无此问题） | **做 M-1** |
| 热启动门 + 冷启动数据 | familyView 1 RTT 空门 + 内存缓存不跨进程 | **做 M-2** |
| APK legacy 双包 | legacy 占 JS 60%（1.75MB/23 文件），APK 死重 | **做 M-3** |

## 2. 实施

### M-1 浏览器引擎下一段预取（web/PWA 朗读连续性）
- audioPlayer.playSegment 开播确认后 `preloadNext(index)`：下一段 cached:true 才取
  （预生成=可缓存 URL；实时合成段带一次性票据，预取无意义），fetch 填 HTTP 缓存，
  playSegment 换 src 时秒出。SSE onSegment 追加到「当前+1」时补触发（开播时它可能还没到）。
- `no-cors` fetch：跨域音频 CDN 无需 ACAO 也能填缓存（opaque 响应按响应头可缓存）。
- 原生路径早退不经过；`preloaded` Set 防重，speakChapter 新会话清空。

### M-2 热启动持久缓存（APK 杀进程重开也秒进）
- listCache 增 localStorage 持久层：home 作用域写穿（~3KB/孩子），读路径内存 miss 回退
  注入内存，SWR/TTL 逻辑不变；PERSIST_MAX=4 防堆积。
- ChildHome children 列表持久缓存：localStorage 命中即按缓存渲染（跳过 familyView 的
  1 RTT loading 门），familyView 照常后台跑，回来 applyFamily 对账+刷缓存；
  **缓存已渲染时网络失败不再顶掉首屏**（bootFromCache 门；V8App 内部 API 自有错误态）。
- 语义：children 列表近乎不可变（选择校验每次都跑）；home 数据 boot 必重验（>60s 恒过期）。

### M-3 mobile 构建去 legacy 双包
- vite.config：mode==='mobile' 不挂 @vitejs/plugin-legacy——Capacitor WebView ≥ Chrome 87
  （legacy targets 本就含 Android >= 8），APK 里 23 个 legacy 文件 ~1.7MB 是死重；
  web/PWA（cdn/默认）保持双包兜底。mobile dist 0 legacy 实测 ✓。

## 3. 明确不做
- 章节正文 ETag/304、TTS 预热端点、书架客户端条件请求：见 §1 判决。
- audio 预取的 saveData 门：每次只预取 1 段（~0.2MB 上限），增益>代价。
