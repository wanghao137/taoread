# docs/107 真机实测性能轮 — 2026-11-07

触发：APK 0.1.8 真机实测三问题（用户）：
1. 加载性能太慢，尤其连家里 WiFi 时整体更慢
2. 底部三个按钮切换（如切到找故事）书单要重新获取，更慢
3. 手机端「今天」页 找故事/英语声音课堂/家庭书架 三按钮各占一整行，太大

## 1. 第一性诊断（全部实测验证）

### 1.1 P0 根因：封面缩图 CDN 缺口（解释 #1 与 #2 的大头）

- 服务器对 312 本公共书全部下发 `media.taostudioai.com` 缩图直链（TAO_MEDIA_PUBLIC_BASE，
  variantUrl()）。AESOP 旧文件 200，但 **10-24 后新增/重建的 3,052 个 art 文件从未上传 R2**
  （sync 状态文件停在被 10-24 21:23：1,008 thumb + 1,008 reader + 1,036 原图）。
- 实测：cover-food-legends / myth-civilization / tales-oldpeter 的 thumb 在 media 域 **404**；
  而源站 /api/media 200（32KB）。前端 fallback 链：thumb 404 → coverArtUrl 原图（~346KB），
  经隧道票据走家宽上行。24 封面 ≈ 8.3MB ≈ 上行瓶颈下 ~87s——**10-20 轮「封面裂图」的
  隐蔽回归**（能显示但极慢），家里 WiFi 感知最重。
- 修复 = 跑现成的 `sync-media-r2.mjs`（增量、断点续传、容量门；老账号 ledger 余 ~3.5GB，
  缺口 ~1.2GB 可容纳）。已从生产 checkout 启动（变体优先→封面原图→章节原图后台补传）。
- 自愈链路：media 域 Cache-Control: public, max-age=31536000, immutable——同步完成即永久快。

### 1.2 #2 tab 切换重新获取：无缓存 + scope 切换 blank

- 「找故事」每次进入/筛选变化都清空重拉（`setPage({books:[]}) + setLoading(true)`），
  无任何缓存；书单 JSON gzip 后 4-5KB（小），感知慢 = 清空→占位→隧道 RTT→再渲染。
- 「我的」tab scope 切换（today↔my）时 `setLoaded(false)` 整页占位 + 全量 248KB raw
  （gzip 48.5KB）重拉；读后返回强制刷新（正确），但 scope 切换也会 blank。
- 启动链已最优（familyView 1 RTT + childHome 并行预取），无需改。

### 1.3 #3 今天页三按钮单列整行

- ≤760px 规则（reading-ui.css:347-354 + upgrade.css ≤760）单列、min-height 76-120px ×3
  ≈ 首屏 1/3。10-27 曾因「两列挤爆文字区」改单列——本次改 3 列紧凑卡（图标上/标签下、
  副文案与箭头隐藏、wide 整行垫底规则重置），与旧修复不冲突（旧修复是两列+大图标；
  新布局文字居中纵排，无负空间问题）。

### 1.4 量化补充

- 服务器压缩正常（books 全量 248KB raw → **48.5KB gzip**；node fetch 测得的是解压后
  字节，需 curl --compressed 测线速字节——测量学坑）。
- 上行实测 ~700KB/s（好于历史 95KB/s 记忆值）；8 个并发探针到 media 域间歇抖动
  （国际网抖动既往坑），不影响结论：修复后封面走 CF 边缘（手机→边缘是下行，不经家宽上行）。

## 3. 明确不做（YAGNI/后续轮）

- ETag/304：客户端 TTL 缓存已使重复切换零网络，服务端改动收益小。
- 书架接口 DTO 裁剪（intro 37KB/28%）：全量 shelf gzip 后 48.5KB，TTL 缓存后首访外无成本。
- 找故事/我的服务端分页改造：48.5KB gzip + 缓存下收益不足，风险大于收益。
- phonics 媒体（309MB，票据私有）走 CDN：需公共内容寻址方案，另轮。
- R2 音频桶扩容/死键清理（8.35GB/10GB 新账号）：内容轮前置项（旧账，非本轮问题）。
