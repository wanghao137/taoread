## 4. 本轮修掉的真实缺陷

### 4.1 P0 级：漏带 token → 401 → 把孩子踢回登录页

`api.ttsVoices() / ttsPreview() / videoGenerate() / videoStatus()` 四个调用方没传 token，而 `request()` 只在显式传 token 时带 Bearer 头 → 后端 401 → 全局 `signOut() + location.assign('/login')`。**孩子一打开阅读器就被踢回登录页。**

修复：`request()` 增加**会话令牌回退**——显式 token 优先，未传时回退 `useSession.getState().token`，调用方不可能再「忘记带」。登录前接口无会话时正确地不带 Bearer。3 条回归测试覆盖三种组合。

### 4.2 P0 级：`navigator.vibrate` 非法调用打断翻章

`haptic('chapter')` 在 `goNext` 里跑在 `loadChapter()` **之前**。实现里直接取 `navigator.vibrate` 函数引用后解耦调用，Chromium 抛 `Illegal invocation`——这个抛出**同步中断了翻章流程**，章节永远不加载。

这个单一缺陷是 e2e 剩余 4 处失败的**共同根因**（章节不推进 → 跨章进度持久化、家长端全流程、视觉截图串联全部跟着挂）。修复：`.bind(navigator)` 绑定 this + try/catch 兜底 + 回归测试断言「vibrate 抛错时不中断调用方」。

**教训：** 跨 4 个测试失败的根因可能是一个。逐个修现象前先找共同上游。

### 4.3 时序类 flaky（误报，非缺陷）

- `night9` 两测例超时：亚秒级用例，但机器高负载（e2e 与单测并行）时 argon2 哈希 + SQLite 落盘偶发 4–6s，默认 5s 误报。→ 服务端 `testTimeout: 20_000` 并注明原因。
- `reports` 调度器测例：固定睡眠 60ms 等 `setInterval(10ms)` 落库，定时器饥饿时失败。→ 改成 `untilCount` 轮询条件，把时序依赖变成确定性断言。

两者单独跑都通过、全量门偶发失败，属于**测试脆弱性**而非产品缺陷，本轮一并加固。
