# 106 — 华为鸿蒙系统上的桃阅读应用分析（2026-11-06）

背景：用户手机=华为鸿蒙。docs/103/104 的路线 B（Capacitor 本地壳 APK 0.1.8）已交付。
本文回答一个第一性问题：**这套资产在鸿蒙上是什么命运，要不要、如何分岔。**

## 0. 物理事实：鸿蒙的版本谱系决定一切

| 版本 | AOSP 兼容层 | APK 可装 | 内核/WebView |
|---|---|---|---|
| HarmonyOS 2.x/3.x/4.x | 有 | **能**（AOSP 运行时） | 华为自研 WebView（Chromium 内核，华为市场更新） |
| HarmonyOS NEXT（5.x，"纯血鸿蒙"，2024Q4 起商用） | **无** | **不能**（只认 .hap/ArkTS 原生包） | ArkWeb（Chromium 内核） |

**判定方法（10 秒）**：设置 → 关于手机 → 看「HarmonyOS 版本」：
- 显示 4.2 或更低 / 无 NEXT 字样 → APK 0.1.8 直接可用，走 §1 适配清单
- 显示 NEXT 或 5.0+ → APK 路线归零，走 §2 ArkTS 路线

另查：设置 → 应用和服务 → 应用管理 → 桃阅读（若已装）；
华为"纯净模式"（设置→安全和隐私）开启时**直接拦截一切侧载**，须先关。

## 1. 路线一：HarmonyOS 4.x 及以下（现有 APK 直接可用）

docs/103 的两个关键决策恰好按无 GMS 假设设计（本地通知而非 FCM），零返工。
但华为与原生 Android 有四处行为差异，全部可引导用户设置化解：

### 1.1 华为电源管理是最大变量（后台朗读/提醒的生死线）
华为省电策略对第三方应用的后台活动最激进（自启动管理+休眠时杀后台+深度睡眠）。
APK 0.1.8 的前台服务朗读与 AlarmManager 提醒必须配合用户手动设置：
- 设置 → 应用 → 应用启动管理 → 桃阅读 → **关闭「自动管理」** → 手动开启
  「允许自启动 / 允许关联启动 / 允许后台活动」三项
- 多任务界面下拉桃阅读卡片 → **加锁**（防一键清理误杀）
- 电池 → 更多电池设置中关闭对该应用的深度休眠（若出现）
- 验收口径：做完上述设置后，docs/104 §3 真机门六项才算有效测试
  （**未做设置就测出「息屏断播」不构成缺陷证据**——那是华为策略而非代码问题）

### 1.2 通知与安装
- 通知权限默认关（HarmonyOS 4 同 Android 13 行为）：首启引导开通知
- 安装：文件管理器点开 APK → 允许「安装未知应用」；纯净模式需先关
- WebView：华为市场可更新「华为浏览器/WebView 内核」；es2018+legacy 双包已兜底旧内核

### 1.3 预期差异点（真机门在华为上的附加观察）
- 拔耳机自动暂停（handleAudioBecomingNoisy）：华为蓝牙栈兼容，预期正常
- 音频焦点：华为来电/语音助手抢焦点行为与 AOSP 一致，预期正常
- 离线 IndexedDB：鸿蒙 WebView 存储正常；注意「清理加速」类功能可能清应用数据

## 2. 路线二：HarmonyOS NEXT（APK 不可装，ArkTS 壳路线）

**第一性结论：全原生重写没必要，「本地壳+原生增强」的路线 B 架构在 NEXT 上可整体平移**：

| 路线B 组件 | NEXT 等价物 | 平移成本 |
|---|---|---|
| Capacitor 本地壳（dist 内置） | DevEco Studio + ArkTS 壳 + **ArkWeb Web 组件加载本地 dist** | 1-2 天（同 M2a 量级） |
| Media3 前台服务朗读 | AVSession Kit + AVPlayer（后台任务长时任务 TaskPool 申报）+ 通知栏媒体样式 | 2-4 天 |
| 本地通知提醒 | NotificationKit（NotificationRequest + 定时提醒reminderAgentManager） | 1 天 |
| 离线 IndexedDB | ArkWeb 同源存储（同 Chromium）+ 文件下载用 FileKit | 复用 |
| dl 渠道分发 | **NEXT 侧载艰难**：无 Play 无第三方市场自由安装；调试签名需 DevEco+华为账号绑定设备（证书约 90 天有效期）；正式分发=AppGallery 上架（软著+ICP+审核，docs/103 §1 门槛全部生效） | **分发是 NEXT 最大成本** |
| API/CDN/内容 | 完全复用（HTTP 层无差异） | 0 |

**NEXT 独有红利**（若未来走到）：跨设备接续（手机→平板接着读）、实况窗（朗读进度上锁屏胶囊）、
小艺语音；均为增强项非首期。

### 2.1 NEXT 路线的工程量与门槛合计
- 代码：ArkTS 壳+音频+通知 ≈ 4-7 天（复用全部 web 资产与 M2b 的编排留 web/播放交原生的架构）
- 分发：调试侧载=个人可走（证书周期性续签）；**给别人装=必须 AppGallery 上架**（软著 1-2 月起）
- 工具链：DevEco Studio（免费）+ NEXT 设备真机调试

## 3. 决策树

1. 手机是 HarmonyOS ≤4.x → **什么都不用做新决策**：装 APK 0.1.8 + §1.1 三项电源设置 → 跑真机门六项
2. 手机是 NEXT → 两条子路：
   a. 只自己用、能接受 90 天续签调试证书 → ArkTS 壳路线（4-7 天，出 spec 走审批）
   b. 要长期稳定分发 → ArkTS + AppGallery 上架材料先行（软著/ICP），代码与材料并行
3. 家里若同时有 NEXT 与 4.x 设备 → APK 0.1.8 服务 4.x 设备，NEXT 设备单独立项，互不阻塞

## 4. 本报告的边界

- 未实测任何鸿蒙真机（本机无华为设备/模拟器）——§1 全部为华为公开行为+既有代码审计推演，
  最终以真机门为准；§2 为工程估算非报价
- 需要你提供的两个信息：①设置→关于手机的 HarmonyOS 版本号 ②是否需要给家庭以外的人安装
  （决定 NEXT 子路 a/b）

## 5. 决策落锁（2026-11-06 用户确认）

- 暂自用 → **子路 a：ArkTS 壳 + 调试侧载**（调试证书约 90 天，DevEco 自动签名续签=重跑一次）
