# 88 · 家长端加载性能与手机端布局优化（2026-10-26）

## 取证方法（先证后修）

真实浏览器双视口（桌面 1440 + 手机 390）走家长端四 tab（今天/内容/足迹/设置），Playwright 记录每 tab 耗时、图片请求数与字节，全页截图定位布局问题；同时审计数据流代码（ContentHub/ParentHome/服务端 `listBooksForParent`）。取证环境：本地 dev.db（与生产同形态：286 本+1322 场景全量插画台账）。

## 性能修复

| 问题 | 根因 | 修复 | 收益 |
| --- | --- | --- | --- |
| 内容页图片慢/占位蓝底 | `ContentHub` 用 `coverArtUrl`（原图）而非服务端已返回的 `coverThumbUrl` | thumb 优先、原图兜底 | 实测单张 326KB→15.8KB（**20 倍**）；286 本滚动浏览 ~93MB→~4.5MB |
| 首屏 DOM/解码压力 | 渐进渲染起步 40 行（书目扩容后偏重） | 起步 24 行，其余走「显示更多」 | 首屏 DOM -40% |

服务端无需改动：`content/family` 已走目录缓存且已返回 thumb 字段，问题纯在前端消费侧。

## 手机端布局修复（全部为 ≤760px 断点增量，桌面零改动）

截图取证的问题与对策：

1. **首屏 ~700px 零内容**（页头+副标题+来源说明+chips 堆叠）→ 隐藏与页头副标题语义重复的 `source-explainer`、页头压缩（h2 24px/副标题 13px），首屏直达搜索与内容。
2. **来源/分类 chips 换行堆叠+边缘截断** → 横向滑动完整可见（隐藏滚动条，44px 触控）。
3. **底部 tab 遮挡卡片** → `.parent-app .wrap` 底部留 `calc(112px + safe-area-inset-bottom)`。
4. **双列 170px 卡内容挤压**（进度条+三按钮竖叠）→ hub 卡改**单列横幅封面（16:9）**，按钮组全宽 44px。
5. **设置页设备行按钮挤压** → `kid-row` 换行+按钮 44px。
6. **足迹页控件散行** → 字号收小+触控 44px，保持自然换行（第一版强加 flex 把 label 文字压成竖排，已回滚为轻量方案——**教训：filter-row 的 label 内文字节点在强 flex 下会被压缩竖排，勿对含裸文本的 label 容器加 flex**）。

## 复验

修复后同脚本回测：手机内容页首屏直达第一张书卡（横幅封面+完整信息+全宽按钮）；足迹/设置页控件整齐；桌面端截图逐像素级无回归。web 143 单测全过、eslint 0、CI 全绿（run 40282125741），生产已部署验证（新构建产物 200）。
