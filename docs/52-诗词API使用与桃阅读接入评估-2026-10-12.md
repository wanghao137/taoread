# chinese-poetry-api 使用与桃阅读接入评估

## 结论

可以作为新增诗词的检索和候选语料来源。推荐先在管理侧选诗、校订，再转为现有 `PackBook` 内容包；儿童阅读、共读和朗读继续使用桃阅读自己的数据与接口。暂不把第三方随机接口直接接入儿童首页，也不全量导入并生成 37 万首的音频和图片。

本次完成源码评估、真实 HTTP 接口验证、现有内容包统计和候选格式转换。没有修改业务代码、导入生产数据库或发布新增内容。接口回执、固定版本源码和转换样例在 `output/chinese-poetry-api-research-20261012/`。

## 实际使用：在线版和自部署版的接口不同

2026-10-12 实测官网首页 HTTP 200。网页中的真实演示接口与 GitHub README 不一致：官网 `/api/v1/health`、`/api/v1/stats`、`/api/v1/poems/search` 均返回 404；以下官网路由返回 JSON、HTTP 200，CORS 为 `*`。

| 功能 | 官网当前接口 | 本次固定 Go 源码的自部署接口 |
| --- | --- | --- |
| 搜索 | `/api/search?q=静夜思&page=1&pageSize=5&lang=zh-Hans` | `/api/v1/poems/search?q=静夜思&type=title&page=1&page_size=5&lang=zh-Hans` |
| 随机 | `/api/poems/random?lang=zh-Hans` | `/api/v1/poems/random?author=李白&type=五言绝句&lang=zh-Hans` |
| 统计 | `/api/stats?lang=zh-Hans` | `/api/v1/stats` |
| 健康 | 本次没有确认官网健康路由 | `/api/v1/health` |
| 列表分页 | 未在官网完成验证 | `/api/v1/poems?page_size=50&after=<响应中的next_cursor>` |
| GraphQL | 本次未验证官网 GraphQL | `/graphql`，支持搜索、分页、统计 |

官网实测用法（Windows PowerShell）：

```powershell
$query = [uri]::EscapeDataString('静夜思')
Invoke-RestMethod "https://poetry.palemoky.com/api/search?q=$query&page=1&pageSize=5&lang=zh-Hans"
Invoke-RestMethod 'https://poetry.palemoky.com/api/poems/random?lang=zh-Hans'
Invoke-RestMethod 'https://poetry.palemoky.com/api/stats?lang=zh-Hans'
```

实际官网统计为 `poems=371313, authors=13577, dynasties=11, types=17`；这是当前官网响应快照，不等于本次固定源码自行构建后的统计。官网搜索响应为 `{data:[], pagination:{page,pageSize,hasMore}, lang}`；随机响应为 `{data:{...}, lang}`。自部署 REST 随机 handler 直接返回诗词对象，分页字段使用 `page_size/total/has_next_page/next_cursor`。适配器必须明确选择接口类型，不能只换 hostname。

自部署可用 Docker，先使用独立本机端口和独立数据卷；下列命令仅为操作说明，本次没有启动该服务：

```powershell
docker run -d --name taoread-poetry-source --restart unless-stopped -p 127.0.0.1:1279:1279 -v taoread-poetry-source-data:/app/data palemoky/chinese-poetry-api:latest
Invoke-RestMethod 'http://127.0.0.1:1279/api/v1/health'
```

正式部署应选择经过验证的 release/digest，避免一直依赖可变 `latest`。镜像启动脚本需要获取数据库，本次未实测镜像下载、启动、磁盘体积或版本。源码需要 Go、CGO 和 SQLite FTS5；完整克隆要带子模块。服务的数据库必须和桃阅读的 SQLite 分开，不能覆盖或共用桃阅读数据库。

自部署配置默认开启每 IP 10 请求/秒、burst 20；每页最多 100，offset 最多 10000，长序列遍历用游标。`char` 随机过滤只能配合 `lang`，不能叠加作者/朝代/体裁。上述都是固定源码规则，官网是否同样限流尚未核实；未进行压力测试。官网的可用性、额度和 SLA 没有承诺，不能成为儿童阅读必需的实时依赖。

## 真实数据质量问题

搜索《静夜思》返回 3 条，其中只有一条标题精确匹配，另两条是正文含有搜索词的长诗。不能把搜索第一条直接作为孩子要读的诗。

官网《静夜思》返回：

> 床前看月光，疑是地上霜。<br>
> 举头望山月，低头思故乡。

桃阅读现有版本为“床前明月光、举头望明月”。这是需要明确底本的版本差异，不应把一种版本直接当成错字自动覆盖另一种。只按标题或上游数字 ID 去重都会出问题。

官网随机样本还把方岳和赵蕃标为“唐”，而这两位诗人的朝代需要按宋代资料复核；说明不能把接口中的作者/朝代自动视为已校订事实。简繁转换也不提供学龄筛选、可靠注音或白话译文。

本次只有限量样本，不能推断全库错误比例。转换出的样例均标记 `publishable:false` 和待审核项。

## 桃阅读已经具备的基础

只读加载当前本地 `ALL_PACKS` 得到 15 本中文诗词书、1,365 章，已有唐诗三百首、李白、杜甫、王维、宋词、诗经、千家诗、元曲等。此统计是本地注册内容，不宣称是当前生产发布量。

现有入口：

| 层次 | 代码 | 接入方式 |
| --- | --- | --- |
| 标准内容 | `apps/server/src/content/types.ts` | `category:'poetry'`，`lang:'zh'`，年龄 3-5/6-8/9-12；一首诗为一章 |
| 正文 | `PackChapter.blocks` | `kind:'poem'`，正文、可选拼音和白话译文；说明用 `note` 块 |
| 注册 | `apps/server/src/content/packs/index.ts` | 只注册完成审核、范围固定的新内容包 |
| 入库 | `apps/server/src/content/seed.ts` | `seedPack`/事务入口，保留已有章节和块 ID，更新版本与权利台账 |
| 目录与阅读 | `apps/server/src/content/service.ts` | 只向普通阅读入口提供 `publicationStatus='published'` 的书 |
| 注音展示 | `apps/web/src/components/art/PoemRuby.tsx` | 按实际换行和逐字音节对齐 |
| 现有语料生成 | `apps/server/scripts/gen-corpus.mjs` | 已使用 chinese-poetry、OpenCC、pinyin-pro；整包生成器会覆写现有包，不能为试点直接执行 |
| 朗读 | `apps/server/scripts/pregen-tts.mjs` | 使用已切换的公共音频上传模块，新音频进新 R2 专用桶 |

当前示例转换结果中，《静夜思》有 2 处同名章节，均与官网正文不同，没有发现相同正文的直接复用项。现有 `publish-chinese-content.mjs` 是固定 33 本书/20 本新增的历史批次脚本，还会执行西游记位置迁移，不适合作为新诗词的通用发布命令。

一个关键发布细节：数据库 `Book.publicationStatus` 默认值是 `published`；`reviewStatus='pending'` 并不会自动阻止目录展示。新试点必须在同一事务中显式设为 `draft`，不能简单调用 seed 后认为它还没上线。

## 推荐实施步骤

1. **确定一个小范围增量包。** 比如春天、月亮或田园主题，先选 20—50 首；优先找现有书库缺少的作品，逐首确定年龄段。保留现有书和章节顺序，避免影响书签、阅读进度和既有音频。
2. **固定来源快照。** 保存原始响应、上游项目/数据提交、抓取时间、标题、作者、朝代、正文和内容 SHA-256。上游数字 ID 仅作来源提示，桃阅读使用自己的稳定书 ID，正文变体单独留痕。
3. **去重和版本核对。** 正文按 Unicode、空白、标点规范化后比较，同时比较标题/作者/朝代；同名不同正文进入人工比较，不能自动覆盖。规范化正文仅用于比对，展示保留校订后的标点与真实换行。
4. **产出待审 CBF 草稿。** `content:string[]` 映射为诗句字符串并用真实 `\n` 连接；`title/author` 映射章节标题；朝代、底本、差异记录在说明和来源材料中。不要凭接口响应编造译文、作者卒年或平台原创声明。
5. **补儿童阅读资料。** 沿用逐字注音格式并校对多音字、生僻字；白话译文自撰、审核，现代来源译文保留授权。分配年龄并校核主题、篇幅、价值表达。示例中的长诗不自动归入 3-5 岁。
6. **隔离试点。** 使用独立数据库/媒体目录入库，显式设 `draft`；核对书、章节、块、权利台账与重复执行结果。不能在本次生产音频索引中直接预生成未发布草稿。
7. **阅读和朗读验收。** 手机和平板检验换行、拼音、长诗分页、白话显示、共读和整章朗读；校对正文与实际朗读。优先复用已有音频，新增音频仍遵循当前 64 kbps 策略和 R2 容量预算，压缩后再确认时长/内容。API 本身不提供音频。
8. **按本次范围正式发布。** 新增通用的窄范围发布入口或使用经过审查的事务，而非复用历史批次脚本。发布前保存数据库快照与内容/媒体清单；需要明确的内容发布指令后才能更新生产。回滚只撤下新包，保留既有家庭数据与旧书进度。

若以后要“每日一诗”或“飞花令”，从已审核、已本地入库的诗池抽取。管理侧可以用上游搜索补充候选，失败时不影响孩子已经能读的内容。

## 存储影响

诗词正文是文本，本次在线请求与候选转换没有产生 R2 存储。真正的大头是新增音频和插图。64 kbps 音频约为每分钟 480,000 字节；假设 50 首各 1 分钟、1 个音色，约 24 MB，1000 首同条件约 480 MB，多音色和译文朗读会继续增加，必须以实际生成统计为准。

若对官网 371,313 首全部按每首 1 分钟生成，单音色就约 178.23 GB，显然不符合每账户低于 10 GB 的目标；这个数字只是相同假设下的估算，不是语料实际音频时长。也不应为每首自动生成多张插画。

现有新增音频辅助模块在目标桶将超过 5.4 GB 时拒绝本次新增上传，但不是 Cloudflare 全局硬配额，也不是并发上传的强原子预留。试点应串行发布并先汇总本批字节，未来其他桶和其他项目仍需一并核算。
