用户需求（2026-10-17）：

因此本文档不是推翻 doc 47，而是给出「**零预算先行版**」：先以最小成本把客户端形态立起来，所有产物保持为 doc 47 对应工作包（A0—A2）的子集，未来进入 doc 47 完整路线时不废弃。

## 1. 零预算约束的硬推导

先把「零预算」翻译成技术边界，避免方案里混入隐性花钱项：

| 常规手段 | 货币成本 | 零预算下结论 |
| --- | --- | --- |
| Apple Developer Program | $99/年 | **不可用** → iOS 无任何商店/TestFlight 分发，唯一免费通道是 **PWA 添加到主屏幕** |
| Google Play 开发者 | $25 一次性 | **不可用** → Android 只能 **APK 直接下载侧载** |
| 国内应用市场（华为/小米等） | 软著、企业资质、代办费 | **不可用** → 同上，且纯净模式侧载限制见 §4.5 |
| 框架本身 | Capacitor / Tauri / PWA 全部免费开源 | 可用 |
| GitHub Actions（public repo）/ GitHub Releases | 免费 | 可用（CI 构建、安装包托管、自动更新源） |
| Cloudflare R2 出口流量 | 免费（egress 不计费） | 可用（APK/exe 下载分发）；**注意**：R2 免费层 10GB 存储已用 8.67GB（docs/48），客户端安装包体积必须控制在数十 MB 级 |
| B2 | 免费 10GB 存储，1GB/日下载 | 备用分发位 |
| 短信验证码、云主机迁移、专业审校 | 有 | **不可用** → 不在本期范围（doc 47 A7/A11/A14 不启动） |

结论：零预算下的客户端分发矩阵 = **Windows exe（GitHub Releases + R2 镜像）+ Android APK（R2 直链侧载）+ iOS PWA（添加到主屏幕）**。三条通道全部不新增货币成本。

## 2. 参考方案与现状盘点

### 2.1 生图工作台（PC 参考）解剖结论

对 `D:\codesolo\taostudio-image-lab` 的源码调研要点（2026-10-17，337 文件/约 8.5 万行）：

- 技术栈：**Tauri 2** + React 19 + Vite 6 + Zustand + Tailwind；打包 `targets: ["nsis"]` 仅 Windows，per-user 中文安装器。
- 成品级工程资产：`tauri-plugin-updater` + minisign 签名自动更新（`update.rs` 带 sha256 校验 + 前端更新弹窗）、`tauri-release.yml` 发布流水线（tag 触发、三处版本一致性校验、从 RELEASE.md 提取更新说明）、最小权限 capabilities/permissions 体系、细粒度 CSP + `freezePrototype`、single-instance、window-state、防深色白闪、拒绝 `_blank` 弹窗、`backgroundThrottling: disabled` 防后台节流。
- 核心架构模式：`platform.ts` 的 `isTauri` 门面 + `db.ts` 双轨路由，**同一份前端代码发布网页版与桌面版两种形态**。
- 关键差异：它是「**本地重壳**」——前端源码打进安装包、数据全本地化（SQLite/文件），**没有「加载远程站点」的轻壳实现**。且其重壳形态是围绕「生图数据不出本机」的产品定位积累的，桃阅读是服务端应用（数据在家庭主机 Fastify + SQLite），照搬重壳没有产品收益。

对上游 gpt_image_playground 的核实：Tauri 2、MIT、约 3.9k star、持续活跃。fork/借鉴均无协议障碍（image-lab 已在 About 页保留 MIT 归因，同样做法即可）。

### 2.2 桃阅读现状盘点（与客户端相关）

结论来自对 `apps/web`、`apps/server` 的源码复核 + docs/39—42、47、56：

- **可安装 PWA 基础已齐**：`apps/web/public/manifest.webmanifest`（standalone、竖屏锁定、192/512/maskable 图标、theme_color）+ `public/sw.js` 轻量透传缓存（2026-09-24 白屏事故后移除预缓存插件，API/导航绝不缓存）+ apple-touch-icon 180 + 双 theme-color + `viewport-fit=cover`。
- **移动端 Web 体验经过三轮真机向打磨**：`pagedReading.ts` CSS 多列分页 + Pointer Events 手势（≤760px 默认翻页模式，公共书与家庭书共用）、360—1440 全断点、44px 触控目标、字号地板 ≥12px、触觉反馈、Wake Lock、离线试点（IndexedDB，5 本/7 天/纯文字）。
- **朗读是服务端合成 + HTML5 Audio 播放**：`audioPlayer.ts`（666 行）段队列 + 字级高亮 + `prime()` 手势解锁 + 哄睡 6 秒渐弱 + **MediaSession 已实现**（锁屏 metadata 与 play/pause/stop）；音频经 R2/签名票据分发。这是移动端最重要的既有资产：客户端壳不需要新造音频管线，只需要解决「WebView 退后台后 JS/音频是否存活」。
- **会话对壳友好**：家庭码 + 设备会话，HMAC JWT（默认 30 天）存 localStorage，`Authorization: Bearer` 头，`VITE_API_BASE` 可配置 API 基址——非 cookie 体制，WebView/Capacitor 可直接用。
- **缺口**：无推送通知代码、无安装引导 UI（beforeinstallprompt 未处理、iOS 无图文指引）、后台播放依赖 WebView JS 存活（doc 47 §7.2 已定性为正式版硬伤）、无任何原生工程、CORS 生产白名单仅 `https://read.taostudioai.com`。

## 3. PC 端方案

### 3.1 三方案对比

| | A. 桌面 PWA（Edge/Chrome 安装） | **B. Tauri 2 远程轻壳（推荐）** | C. Tauri 2 本地重壳 |
| --- | --- | --- | --- |
| 货币成本 | 0 | 0 | 0 |
| 开发量 | ≈0（今天就能装） | **2—4 人日** | 15 人日以上，且持续双打包 |
| 形态 | 浏览器托管独立窗口 | 独立 exe、自有图标/窗口/进程 | 独立 exe，前端打进包 |
| 单实例/防误操作/深链 | 无 | 有（Rust 侧实现） | 有 |
| 前端更新 | 随网页即时 | 随网页即时（壳仅自身升级才发版） | 每次发版都要重打包+全量更新 |
| 离线 | 与网页相同（sw.js + 离线试点） | 与网页相同 | 可做深度本地化 |
| 主要短板 | 无品牌 exe、无单实例、不可控行为垫片 | 依赖网络可达生产站点 | 收益与桃阅读产品形态不匹配（数据本就在服务端） |

推荐 **B**，理由：用户明确要客户端形态且有现成参考工程；轻壳把 90% 的工程资产（安全配置、更新、发布流水线、窗口行为）从 image-lab 直接移植，而把 100% 的业务更新留在网页侧——**壳的版本频率极低，这是单人维护能长期承受的形态**。A 作为 B 的过渡基线保留：在 B 发布前，设置页放「用浏览器安装桌面应用」指引即可。

不推荐 C 的关键论据：image-lab 重壳价值来自「数据不出本机」的隐私承诺和离线生图场景；桃阅读的数据（家庭书、进度、朗读缓存）天然在服务端，重壳要么仍需联网（那与轻壳无异），要么要把 11 万行服务端业务重新本地化（等于重写一个产品）。离线阅读的合理边界仍是现有「公共书图文/试点离线」路线，由网页层演进，与壳形态解耦。

### 3.2 推荐架构（方案 B 详细设计）

新目录 `apps/desktop/`，独立 Tauri 2 工程（不复制 image-lab 的 React 业务层）：

```text
apps/desktop/
  src-tauri/
    src/main.rs          # 极薄：入口
    src/lib.rs           # 窗口创建、single-instance、window-state、防白闪、导航拦截
    capabilities/        # 只授 core 窗口类最小权限；【不给 remote 任何 IPC 权限】
    tauri.conf.json      # 见下
    windows/installer.nsi  # 中文 per-user 安装器模板（移植 image-lab）
    icons/               # 从 apps/web/public/icons 生成全尺寸
  .github/workflows/desktop-release.yml   # 移植 image-lab tauri-release.yml
  RELEASE.md                              # 分版本更新说明（CI 提取进 Release 正文）
```

**核心配置要点：**

1. **远程加载 + 零 IPC**：WebviewWindow `url` 指向 `https://read.taostudioai.com`（开发环境 `http://localhost:5173`）。Tauri 2 的 capabilities 支持 `remote.urls` 白名单，且**远程页面默认拿不到任何 IPC 命令**——本方案给 remote 授权的命令集合为空，仅 Rust 侧监听事件。这样即使站点出现 XSS，也不存在「网页→原生命令」的提权面（Bishop Fox 对 Tauri 类框架的攻击面分析中，远程内容 + 宽授权是主要风险组合，零授权即消除）。`dangerousRemoteDomainIpcAccess` 等价物不启用。
2. **导航拦截在 Rust 侧**：`on_navigation` 回调判断目标域——`*.taostudioai.com` 放行，其余（隐私政策外链、微信读书入口、未来任何外链）一律 `shell.open` 转系统浏览器并取消导航。不依赖前端 JS，天然防绕过。
3. **行为垫片用 `initialization_script` 注入**：屏蔽 F5/Ctrl+R/Ctrl+P 与右键菜单（保留 F12/缩放/Ctrl+F，与 image-lab 行为表一致）。注入脚本无 IPC 也能 `preventDefault`。
4. **窗口与生命周期**：single-instance（二次启动置前）、window-state 记忆位置尺寸、读注册表按系统主题设背景色防深色白闪、`backgroundThrottling: disabled`（**保证朗读音频在窗口最小化/遮挡时不被 WebView2 节流**——这是 PC 端「边做别的事边听书」的关键）、关闭即退出（V1 不做托盘，与 image-lab 一致；孩子端误关由网页内确认弹层承担）。
5. **自更新**：`tauri-plugin-updater` + **新生成的 minisign 密钥对**（绝不复用 image-lab 密钥；私钥入 `%USERPROFILE%\.tauri\`，公钥进配置；密钥丢失 = 存量用户收不到更新，参照 image-lab docs/desktop-client.md 保管规程）。endpoints 双通道：GitHub Releases `latest.json`（主）+ R2 镜像 `latest.json`（国内可达性兜底，updater 支持多 endpoint 顺序回退）。壳版本频率极低（仅 Tauri/WebView 层变更才发版），前端功能更新随网页自动生效。
6. **身份与存储**：壳加载远程域，WebView2 独立 user data folder，localStorage 首次为空 → 用户走一次家庭码登录（30 天令牌），可接受；不做原生凭据迁移。
7. **音频/朗读**：复用网页 `audioPlayer.ts` 原样运行。边界声明：WebView2 内 MediaSession 不会接入 Windows 系统媒体浮层（SMTC），锁屏/媒体键控制不可用——PC 场景（窗口常开听书）影响小，列入已知边界而非本期目标。
8. **标识**：identifier 建议 `com.taostudio.taoread`（与 image-lab `com.taostudio.image-lab` 同族）；productName「桃阅读」；深链 `taoread://` 列 V1.1（家庭邀请/扫码场景），V1 不注册协议。

**V1 功能范围（必须 / 不做）：**

| 必须（V1） | 明确不做（V1） |
| --- | --- |
| NSIS 中文 per-user 安装器、桌面/开始菜单图标 | 系统托盘 |
| 单实例、窗口状态记忆、防深色白闪 | 本地 SQLite/文件存储层 |
| 外链转系统浏览器、行为垫片 | 深链协议注册 |
| tauri-plugin-updater 自更新（GitHub + R2 双源） | 系统通知/每日阅读提醒（V1.1，走 image-lab 的 notification 插件替换模式） |
| GitHub Actions 全自动发布流水线 | macOS/Linux 打包（无签名与真机条件；mac 用户继续用网页/PWA） |

**构建环境要求**（一次性，与本机现状核对）：Rust stable MSVC + VS 2022 Build Tools + WebView2 Runtime；Node 22。doc 47 探测时本机有 Node 与 JDK 17、无 Rust——安装 Rust 工具链是 A0 前置步骤。

**验收清单**：安装/卸载/覆盖升级干净；双击二次启动只置前不双开；最小化 30 分钟朗读不断；外链全部走系统浏览器；F5/右键被拦截且 F12 可用；深色系统启动无白闪；发一个 `v0.1.0` 测试 tag 走完整 CI→Release→应用内检测更新→被动安装闭环； CSP/权限审计（remote 零命令）。

### 4.1 路线对比（加入零预算维度）

| 路线 | 货币成本 | 复用 | 后台听书 | 分发（零预算下） | 与 doc 47 关系 |

判断依据：doc 47 已系统论证 Capacitor 优先、RN 后备。零预算不改变这个技术排序（所有框架免费），只改变**分发与范围**：不进商店、不做监护人账号/短信、不做完整离线账本。因此推荐 **M0 → M1 →（条件触发）M2** 三阶段，每阶段独立可交付、独立可停止。

### 4.2 iOS 免费路线的事实基础（关键调研结论）

- **存储豁免**：WebKit 官方文档明确「添加到主屏幕的 Web 应用，其第一方域**豁免 ITP 7 天存储清除**」——已安装 PWA 的 localStorage 令牌/IndexedDB 离线书不会被 7 天不用就清掉；普通 Safari 标签页则会被清。**这是必须做安装引导的硬理由**（不装 = 7 天后掉登录、丢离线书）。
- **Web Push**：iOS 16.4+ 仅对已安装主屏 Web 应用开放（免费、VAPID 自管、可从现有 Fastify 用 web-push 库发送），是未来「家长阅读提醒」的零成本实现路径；本期不做（doc 47 定调首发无营销推送），仅记录通道存在。
- **后台音频**：`<audio>` + MediaSession 在 iOS PWA 锁屏场景「可用但有可靠性报告」，社区长期痛点。处置：**真机门禁**（M0 验收含锁屏 30 分钟跨章测试），不达标不硬撑——iOS 的哄睡锁屏需求如实降级为「亮屏播放 + 自动渐弱」，彻底解决仍需回到 doc 47 原生路线（届时才有 $99 账号的前置意义）。

### 4.3 M0：PWA 强化（双端立即可用，2—3 人日）

| 项 | 内容 | 验收 |
| --- | --- | --- |
| 安装引导 UI | Android：捕获 `beforeinstallprompt`，设置页/登录页出「安装桃阅读」按钮；iOS：检测 Safari 且非 standalone 时出「分享→添加到主屏幕」图文指引（可关闭，localStorage 记忆不再弹） | 双端各一台真机完成安装且图标/启动画面/全屏正确 |
| iOS standalone 专项真机门 | 锁屏朗读 30 分钟跨章、来电/耳机打断、哄睡渐弱、锁屏返回后字级高亮恢复、7 天豁免抽查 | 全过或明确降级结论（记录到本文档附录） |
| manifest 微调 | 补 `id`、`description`、`screenshots`（Android 安装弹窗富化） | DevTools Installability 无警告 |
| MediaSession 补全 | 上一段/下一段、seek 后台命令核对（现仅 play/pause/stop） | 锁屏可控 |

M0 同时服务三个平台（含 PC 桌面 PWA 基线 A），是纯网页层改动，不引入任何原生工程。

### 4.4 M1：Capacitor Android APK 侧载（4—8 人日）

工程要点（全部沿用 doc 47 §6 结论，去掉其中依赖预算的部分）：

1. **工程**：`apps/mobile/`，Capacitor 8 + `@capacitor/android`，web 资源取 `apps/web` 的独立 mobile 构建（`VITE_API_BASE=https://read.taostudioai.com`，**不注册网页 SW**，媒体相对路径统一经 `VITE_API_BASE` 解析为绝对 URL——`api.ts:5` 已支持）。
2. **CORS**：Capacitor Android webview origin 为 `https://localhost`，服务端 `TAO_ALLOWED_ORIGIN` 增加该 origin；生产为 env 改动 + 重启（须遵守既有「迁移/变更须停服务跑」运维惯例，选低峰窗口）。
3. **会话**：V1 沿用 localStorage（Android WebView 持久化），**Keychain/Keystore 迁移明确列为已知边界**，留给 doc 47 A7（其触发条件是公开发行，不是侧载自用）。
4. **图标/启动屏**：现有 512 图标 + Splash 插件；品牌延续 manifest 资产。
5. **签名**：自生成 keystore，密码不入库不入 git，**密钥即身份**——丢失则只能换包名重装，保管规程写入 ops 文档。
6. **分发**：APK（≤30MB，绝不带书库；对照 doc 47 §2.2，2.3GiB 音频绝不随包）上传 R2 经 `audio.taostudioai.com` 同款 Worker 模式出直链（R2 egress 免费；存储增量几十 MB，R2 剩余 1.33GB 容量足够，B2 为备用）；自建 `/download` 页：版本号、SHA-256、安装指引（允许未知来源；华为/荣耀需关闭纯净模式；小米电诈拦截提示）、「覆盖安装升级保留数据」说明。
7. **应用内升级提示**：不做热更新（doc 47 §10.5 定调 V1 不引入绕过商店的热更体系，侧载场景同样适用）；启动时查一个轻量版本端点，落后则提示跳下载页覆盖安装。
8. **真机门禁**（doc 47 §5.1 的侧载简化版）：分页正反 200 次手势无错页；锁屏朗读 30 分钟跨章（记录小米/华为后台电池策略差异）；杀进程重启恢复位置；飞行模式读已缓存内容；覆盖安装数据保留；400 元档低端机流畅度抽查。

### 4.5 零预算路线的诚实边界

| 边界 | 说明 |
| --- | --- |
| iOS 无原生 App | 零预算下不可解。iPhone/iPad 体验上限 = PWA；「锁屏哄睡可靠性」可能达不到原生水准，需真机数据说话 |
| 侧载摩擦 | Android 用户需手动允许未知来源；华为纯净模式默认拦截；无法静默更新 |
| 无推送 | 每日阅读提醒在 PWA/M1 内只能站内实现；Web Push 与原生推送都留待后续（Web Push 是免费路径，已在 §4.2 记录） |
| 合规姿态不变 ≠ 免除 | 零预算路线的实质是「**维持现状分发姿态**：家庭码制、免费、不上架、不公开推广」——与今天网站的法律位置相同，不新增风险面。**一旦要公开推广或进商店，doc 47 §11（备案/出版/AI 标识/儿童隐私）与 §14 全部适用，届时零预算假设作废**。APK 分发页不采集任何数据、不放统计脚本，与该姿态一致 |
| 服务端单点不变 | 客户端全部指向现有生产（家庭主机 + Tunnel + SQLite），不改变其容量/可用性边界（doc 47 §10.1） |

## 7. 风险表

| 风险 | 触发 | 应对 |
| --- | --- | --- |
| iOS PWA 锁屏朗读不可靠（社区有报告） | M0 真机门失败 | 如实降级为亮屏播放；彻底解决需回到 doc 47 原生路线（含 $99 账号），提交用户决策 |

| WebView2/GitHub 下载国内可达性 | 用户反馈更新慢/失败 | updater 多 endpoint（R2 镜像）；APK 主分发位放 R2 而非 GitHub |

| minisign 私钥/keystore 丢失 | 保管不当 | 保管规程写入 ops 文档；keystore 丢失 = 换包名重装（家庭小范围可承受） |

## 8. 待用户拍板的决策点

1. **PC 采用轻壳方案 B**（推荐）还是先用桌面 PWA 基线 A 观察一阵？涉及 identifier `com.taostudio.taoread` 与产品名确认。
