## 0. 一句话结论

本轮的核心收益不是「加了功能」，而是**把已经算好但被浪费的数据接上了 UI**：服务端 TTS 早已返回字级时间轴，audioPlayer 早已逐帧算出 `charIndex`，但接口没声明、渲染层没消费。修复这条链路后，零后端成本拿到了按年龄分级的 karaoke 式逐字高亮——这是本轮性价比最高的一项。

同时按实证证据**砍掉了**三个候选功能（阅读中问答弹窗、点击热点、小游戏），并把一个会制造焦虑的指标（预计阅读时长）从孩子端迁移到了家长端。

## 3. P0 交付明细

### P0-1 朗读高亮按年龄分级（本轮重点）

**问题**：`audioPlayer` 用 rAF + 二分查找逐帧算出了当前字符下标，但 `TtsProgress` 接口没有声明这个字段，`ReaderScreen` 也没有消费——数据算了，界面没用。

**做了什么**：

1. **接口修复**（`apps/web/src/lib/tts.ts`）
   `TtsProgress` 新增必填 `charIndex: number`。`-1` 表示句刚开始尚未定位到字符（Web Speech 回退路径恒为 -1）。

2. **渲染层接通**（`apps/web/src/pages/child/ReaderScreen.tsx`）
   新增 `renderSpeakingText()`：把当前句拆成单字，正在读的字加粗，已读的字恢复全透明度，未读的字半透明。**色盲友好**：靠字重 + 透明度区分，不靠红绿。

3. **粒度按年龄分流**
   ```
   auto（默认）→ 6-8 岁 / 9-12 岁：逐字
                3-5 岁：          逐句
   ```
   分流依据见 docs/17 §2：karaoke 高亮的实证样本多为 8-9 岁，3-5 岁证据缺失，且中文正字法路径与拼音文字不同。低龄儿童逐字高亮反而会增加认知负荷，因此默认只给逐句。

4. **家长/孩子可手动覆盖**
   阅读设置抽屉新增「朗读跟着读」四档分段控件：跟着年龄 / 逐字 / 逐句 / 关掉。`aria-pressed` 标记选中态，下方解释文案随档位变化。选择在阅读器生命周期内保持。

5. **测试**
   - `apps/web/test/highlight.test.ts`：8 条单测，覆盖 auto 分流、家长显式设置优先、off 全关、`charIndex=-1` 整句不可分段、逐字 active 标记、越界防御、emoji 代理对（用 `Array.from` 而非 `String.length`）、接口字段守卫。
   - `e2e/demo-content.spec.ts` 新增用例：四档可见 + auto 默认选中 + 切换翻转 + 关闭再开记住选择。

### P0-2 时长估算去焦虑化

**问题**：孩子端书卡显示「约 N 分钟读完」。对一个还没开始读的孩子，这是在告诉他「你还有这么多苦要吃」。

**做了什么**：
- `BookShelf.tsx` 移除剩余时长显示，改为中性信息「N 章 / N 小节」（未开始）或「N 章」（有进度）。
- 时长估算没有删，而是**迁移到家长端** `ContentLibrary.tsx`：「预计 X 分钟 · 约 Y 字」——家长选书时需要这个信息，孩子不需要。
- 搜索空态的示例词从行内小字改为 chip 按钮（`min-h-touch`），触控目标达标。

### P0-3 默认排版基线

依据 Hakvoort 2017（词间距加大对儿童阅读理解有正面影响）：
- 诗块（poem）：`letterSpacing: 0.04em`
- 正文块（text）：中文 `0.04em`，英文 `0.01em`（英文词间已有空格，再加字间距会过宽）

### P0-4 动效与叙事同向审计

排查所有持续循环动效，确保它们「辅助叙事」而非「单纯吸引注意力」：
- `ReaderScreen` 加载圈：`useReducedMotion` 为真时降级为呼吸式透明度渐变（`MOTION.twinkle`），不再旋转。
- `BookShelf` 加载吉祥物：原来的 1.4s 裸上下循环且**没有 reduced-motion 门控**，已修复——`reduced` 为真时不动，否则才 `MOTION.float`。
- `CelebrationScreen`：月亮与成就卡在 reduced 模式下降级为 `MOTION.pageFade`。

## 4. 明确「不做」的决策（本轮用否证证据砍掉的候选）

这是本轮比 P0 更重要的产出。以下功能在候选清单里看起来都「有利于阅读」，但实证证据不支持：

| 候选功能 | 否证依据 | 决策 |
|---|---|---|
| 阅读中插入式问答弹窗 | Bus 2025：交互式绘本对阅读理解效果 ≈ 0 | **不做** |
| 点击热点（图中可点元素） | 同上，且热点会打断叙事流畅性 | **不做** |
| 小游戏/互动奖励 | 多项研究显示对阅读理解为**负效应** | **不做** |
| 阅读障碍专用字体 | Wery & Diliberto 2016：零效应 | **不做** |
| 蓝光眼镜式护眼宣称 | Cochrane 2023：证据不支持 | **不做**（不做任何护眼宣称） |
| 跟读打分 | 无正面证据，且打分=评价=焦虑源，违反红线 | **不做** |

**引用诚实性修正**：此前材料中引用过 Lillard 2011「快节奏动画损害执行功能」，该结论已被原作者 2015 年推翻——只有**奇幻内容**对 EF 有影响（Hinten 2025 确认 d=−0.244）。已从交付材料中修正，避免用被推翻的证据支撑产品决策。

## 5. 战略层锚点（为什么做共读而不是做「更多功能」）

Sanders 2023（NHB，102 项元分析，193 万儿童）：屏幕读写与语言能力 r=−0.14，但**共看（co-viewing）翻转为 r=+0.15**。

这决定了桃阅读的差异化不是「更花哨的儿童 App」，而是**把家长拉进阅读现场**。因此本轮的家长侧投入（时长估算迁移、共读对话量指标）不是附庸，是主线。

## 7. 本轮踩坑记录

| 坑 | 现象 | 解法 |
|---|---|---|
| Prisma 迁移分叉 | dev.db 早期 db push 过，`migrate deploy` 报 P3009 卡住 | `migrate resolve --applied <name>` 标记已应用；测试库单独 `TAO_DATABASE_URL='file:./test.db' migrate deploy` |
| `prisma generate` EPERM | 后台 gen-video 进程占 query engine DLL | 精确 taskkill 自己的 tsx PID（不用 `taskkill //IM node.exe` 全杀，会误伤其他项目），generate 后重跑（脚本幂等） |
| Playwright 找不到 baseURL | 报 "Cannot navigate to invalid URL" | 配置在 `e2e/` 不在仓库根，必须 `npx playwright test --config e2e/playwright.config.ts` |
| E2E 选择器随状态漂移 | 「开始读」按钮在有进度后变「接着读」 | 全部用 `/开始读\|接着读/` 正则匹配 |
| E2E Escape 关不掉 Sheet | `keyboard.press('Escape')` 无效 | 用实际的 `getByRole('button', { name: '关闭' })` |
| MOTION 预设名 | 引用了不存在的 `MOTION.fadeIn` | 实际预设：pageFade / riseIn / sheetIn / listItem / pageForward / pageBackward / breathe / float / twinkle / tap / staggerContainer |
| count-content.mjs 无法运行 | 导入 `.js` 后缀但源码是 `.ts` | 用 `npx tsx scripts/count-content.mjs` 跑 |
| Web 单测不能渲染 JSX | vitest `environment: 'node'`（无 jsdom） | 只测纯逻辑，把组件内的判断函数抽成可独立复刻的纯函数 |
