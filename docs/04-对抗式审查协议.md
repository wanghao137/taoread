# 桃阅读 对抗式审查协议（每夜必执行）

> 适用范围：夜间执行计划（[03](./03-夜间执行计划.md)）的每一个夜班会话。
> 核心信念：**代码在被证明无罪之前一律推定有罪。** 审查的目的不是确认"做完了"，而是主动找出"哪里会坏"。

---

## 三道门（顺序执行，全过才算收夜）

### Gate A — 自动化验证（机械门）

```
npm run verify   # = typecheck + lint + unit（+ e2e 自第 11 夜起）
```

- 必须全绿；禁止 skip 测试来"变绿"（确需跳过必须记日志并登记 P2）。
- 覆盖率底线：`services/weread/*`、`lib/crypto`、认证中间件 **≥85% 分支覆盖**；其余 ≥70% 语句覆盖（`vitest --coverage`，自第 2 夜起每夜输出到日志）。
- 红了就是红了：先修复，再继续后面的事。

### Gate B — 对抗式代码审查（子代理门）

1. **派出审查者**：使用 `code-reviewer` 类型子代理，一次审查范围 ≤ 当夜改动（马拉松夜按模块分批派发）。审查提示必须包含：
   - 审查对象文件清单与本次改动意图（来自当夜任务）；
   - 本协议 §审查宪章 与 §严重级定义；
   - 需求依据：`docs/02-开发计划书.md` 对应章节、微信读书 skill 文档中相关接口文档；
   - 输出格式：`编号 | 文件:行 | 严重级 | 问题 | 证据 | 建议修复`。
2. **修复循环**：P0/P1 当夜修复 → 复审（同一审查者二次确认"已修复且未引入新问题"）→ 通过；P2 记入 `docs/bug-register.md` 并排期。
3. **记录**：每轮发现与修复结果写入当夜日志（发现数/修复数/复验结论），不做静默修复。

#### 审查宪章（审查者必须逐类排查）

| 类别 | 排查项 |
|------|--------|
| 逻辑与边界 | 空值/未定义、越界、除零、可选链缺失、默认值吞错 |
| 异步与并发 | 未捕获 Promise、竞态（连点/双开/重入）、事件监听泄漏、cron 重入 |
| 错误处理 | catch 后吞错、错误信息含敏感数据、重试放大故障、降级路径缺失 |
| 数据一致性 | 事务边界、幂等（重复收尾/重复解锁）、时区（统一 Unix 秒）、单位（时长秒） |
| 安全 | 密钥泄漏路径（日志/回显/错误/URL）、越权（跨家庭读写）、注入（Prisma 参数化）、CORS、缓存键家庭隔离 |
| 合规 | 儿童信息零采集、无面向孩子推送、软限与睡觉模式服务端校验、无焦虑话术 |
| 需求符合性 | 与 docs/02 及 weread skill 文档的口径偏差（字段臆测、数量口径、deepLink 拼接禁令） |
| 前端专用（第 5 夜起） | 状态死角（loading/error/empty 三态）、内存泄漏（定时器/订阅）、reduced-motion、防连点、超长文本、低端机性能 |

#### 严重级定义

- **P0**：崩溃/数据丢失/安全漏洞/隐私违规/需求红线违反（负向清单）——当夜必须清零。
- **P1**：功能错误或明显退化、核心路径不可用——当夜必须清零。
- **P2**：体验瑕疵、代码质量、文档滞后——登记排期，验收日前全部处置。

### Gate C — 行为走查（人肉门，由夜班会话模拟执行）

1. 按当夜"验收清单"逐条走查（启动应用实际操作，或 e2e 覆盖后以 e2e 为准）；
2. 回归抽查上一夜的 3 条关键路径（防止修新坏旧）；
3. UI 相关夜：每关键页截图存 `docs/screenshots/night-NN/`，与设计系统对照；
4. 走查结果（通过/不通过 + 证据）写入日志。

## 收夜标准（全部满足才允许结束）

- [ ] Gate A 全绿（覆盖率达标）
- [ ] Gate B 零未决 P0/P1，复审闭环
- [ ] Gate C 验收清单全过 + 回归抽查通过
- [ ] 日志/登记册已更新，git 已提交
- [ ] 给下一夜留了交接便签

**时间盒纪律**：07:30 后禁止开始新任务，只允许：修复、审查、走查、日志、提交。宁可少做一个功能，不可带着 P0/P1 收夜。

## 审查者提示词模板（夜班直接复用）

```
你是对抗式代码审查员，任务：证明以下代码有缺陷。立场：代码在被证明无罪前一律推定有罪；宁可误报不可漏报。
审查对象：<文件清单>
改动意图：<当夜任务摘要>
需求依据：docs/02-开发计划书.md §<章节>；<weread skill 接口文档要点>
排查清单：<粘贴本协议"审查宪章"表>
严重级：<P0/P1/P2 定义>
输出：编号 | 文件:行 | 严重级 | 问题 | 证据 | 建议修复。若无发现，输出"未发现 P0/P1"并说明你排查过的类别。
```

## Git 纪律

- 每完成一个任务一个提交，Conventional Commits（`feat:`/`fix:`/`test:`/`docs:`/`chore:`）；
- 禁止 force-push、禁止改写历史、禁止提交 `.env`/密钥/大体积截图；
- 里程碑夜（第 4/10/12/16 夜）打 tag（`m-a-done`、`m-b-done`、`m-c-done`、`v1.0.0`）。
