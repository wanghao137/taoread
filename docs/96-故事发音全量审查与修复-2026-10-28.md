# 96 · 故事发音全量审查与修复（2026-10-28）

## 1. 结论（TL;DR）

中文书的朗读发音缺陷有两个正交来源，本轮都已修复并部署：

1. **音频层**：故事书里嵌入的古典诗文（木兰诗、迢迢牵牛星、山海经、三字经「窦燕山」、唐诗三百首「胡骑」、宋词「脉脉」等）含大量罕读字/文读音，stepaudio 按默认音读出（可汗读 kěhàn、胡骑读 húqí、天雨粟读 yǔ、脉脉读 mài…）。此前发音保护词典只有《百家姓》+8 句诗。→ 新增 `storyPronunciation` 词典（21 条词/行级同音字替换），受影响 21 段音频已按新键预生成。
2. **显示层（注音）**：pack 源码注音存在真错标（木兰「军帖 tiě→实为 tiē」「十二卷/卷卷 juǎn→实为 juàn」「愿为市鞍马 wéi→实为 wèi」「胡骑 qí→实为 jì」、山海经「辟就 pì→通避读 bì」、诗经「载笑载言 zǎi→实为 zài」「拮据 jù→实为 jū」「黄发 fā→实为 fà」、垂老别「同行 háng→实为 xíng」、长恨歌/宋词「睡觉 jiào→睡醒义 jué」）——孩子照注音识字会学错。→ 全部修正入库。
3. **连带发现并根治**：tangshi-300 有 57 个诗块把版本校勘注「(某某 一作：某某)」混在朗读文本里——stepaudio 会把注记读出声（可听见的怪音），且 8 个块的注音 token 数与汉字数不等（原始数据损坏：跨行注组、缺闭括号），一直挡住该书版本审批。→ 注记从 text/pinyin 剥离（artPrompt 保留），诗正文逐字未动。

## 2. 审查方法（第一性原理，可复现）

「发音对不对」的最终裁判是人耳，机器无法直接验证音调（SenseVoice ASR 只输出字，不输出音素）。因此审查拆成两个可机器枚举+人工裁决的面：

- **注音面（显示层，可完全机检）**：`output/pron-audit-20261028/scan.mts` 用 pinyin-pro 上下文注音对照全部 286 本中文 pack 的 1534 个注音块、逐字比对 115,687 个注音字。检出 1,377 处疑点（音调类 1,309 / 声韵类 68）。
- **朗读面（音频层输入）**：与 TTS 完全同口径（text+poem 块、chunkText 切分）提取全部朗读文本，对 80 个高风险多音字普查（65,578 处原始命中），按「故事书+语境歧义+stepaudio 已知失败类别」收敛。

**118 条非变调疑点逐条人工裁决**（`ruby-adjudicate.md`），关键发现：**大多数「疑点」是 pinyin-pro 判错、pack 注音反而是对的**（白发 fà、可汗 kèhán、朝朝 zhāo、天雨粟 yù、岂弟 kǎitì、燕赵 yān、参 shēn、脉脉 mò、竞读 zhòng→chóng 等 100+ 处 pack 正确）——即 pack 的注音质量整体很高，真错是上面列出的少数几处。但**这些正确注音从未进入 TTS**：显示层对的、音频层错的，正是「音调不对」的主源。

多音字裁决原则（写入词典注释）：只收「全语料无歧义的词/行级条目」；还/长/重/着 等高频多音字在白话语境下 stepaudio 正确，不收录、不折腾缓存键。有意不改的编辑约定：诗经「大夫 dài fu」6 处一致（上古音传统，非笔误）、琵琶 pá、千家诗「睡觉 jiào」（近代白话义）。

## 3. 修复机制（沿用既有架构，缓存键自动轮换）

`cacheKey` 本就内建修正盐：`spoken !== text` 时把修正后文本拼进哈希。因此：

- `narrationInput`（client.ts）与 `cacheKey`（cache.ts）同步接入 `storyPronunciation`；
- 受影响段落键自动更换→旧（错误发音）音频失活，pregen 只补新键（19+段）；
- 未受影响段落键零扰动（修正盐标签不变，poetry 修正段落键也不变）。

词典每条注明位置/应读/风险依据；`test/storyPronunciation.test.ts` 把「词典命中清单」快照化——语料漂移或新命中必须人工过目，防止静默回退。

## 5. 环境坑（本轮新增）

- **tsx -e / node -e 在本机 GitBash 吞输出**：内联脚本 stdout 经常丢失，一律写脚本文件再跑。
- **prisma/prod.db（仓库内）是空壳**：真生产 DB 在 `D:/taoread-prod/apps/server/prisma/prod.db`；memory 里「真 DB=prisma/prod.db」需按此理解。
- **生产是 git clone（main）**：部署=提交推送→生产 pull→迁移/重播种→媒体→重启（NSSM 服务 `taoread-api`，`bin/restart-api.cmd`）；不再是文件直同步。
- **R2 容量锁**：`scripts/lib/r2-capacity.mjs` 8GB 警告/9GB 停止，账号已近上限，上传被护栏拒绝（`R2 capacity lock unavailable`）——不绕过；未上传段由运行时源站兜底（`uploaded=false` → `/api/media/tts-public/`）照常正确发音，只差 CDN 边缘加速。**R2 容量治理（含本轮产生的死键）需要单独一轮**：旧键 mp3 滞留属正常换键行为，按 clean-media-r2 的引用集清理。
- **源文件换行是字面 `\n` 转义**：对 pack 源码做正则 codemod 必须按 `\\n` 匹配，按真实换行写跨行模式永远失配（本轮 codemod 写到 v3 才对）。
- **changeReview 会做拼音结构校验**（token 数=汉字数）：挡住的恰好是坏数据——审批门第一次真正发挥作用。

## 6. 遗留与建议

1. **R2 容量治理**：账号近 9GB 停止线，死键（含历次换键累积）需要跑 `clean-media-r2.mjs --tts-dead` 一轮；否则新音频只能源站兜底。
2. **发音的最终验收仍是人耳**：本轮修复的是「确定会错的罕读」与「注音错标」，引擎对高频多音字的读音无法机器验证。建议下次给娃读木兰诗/唐诗三百首时重点听：可汗、胡骑、军帖、燕山、金柝、脉脉、天雨粟、十一处校勘注段落（应已无怪音）。
3. **pinyin-pro 不是裁判**：它自己的多音字错误率不低（还钱 huán、白发 fā 都会判错），只能当检测器。
4. 诗词类（poetry-shijing 氓/鸱鸮/閟宫等）本轮只修了显示层注音，音频层未加替换条目（载笑载言 zài 等中风险项）——如果试听发现仍错，按 storyPronunciation 同模式加条目+重生成即可。
