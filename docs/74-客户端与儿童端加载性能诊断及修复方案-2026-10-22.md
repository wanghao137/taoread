# 桃阅读客户端与儿童端加载性能诊断及修复方案

日期：2026-10-22。任务范围：分析 PC 应用、Android APK 加载慢，列出可执行修复方案。本轮没有修改业务代码、提交、推送或部署。

## 1. 结论

当前慢是几段等待叠加，不能归结为“手机性能差”或“套壳必然慢”：

1. **PC 冷启动依赖公网整站加载**。它是远程站点壳，安装应用没有消除 HTML、脚本和字体的公网等待。入口确实采到明显的建连及首字节波动。
2. **儿童今天页的主要阅读入口依赖全量书目**。只展示几本推荐，仍先获取并转换全部公共书目，完整目录准备完才启用继续阅读按钮。前端每次显示 24 本不等于接口分页。
3. **首屏工作缺少优先级隔离**。今天页发起约 10 项读取，包括周报、成就、最近阅读、英语下一课等；它们并非全部硬阻塞按钮，但会增加启动期请求和渲染竞争。
4. **远程页面使用两份共 2,545,968 字节的中文字库**。公网补测已完成两份下载。APK 内置这些资源，因此这里不能算作 APK 每次额外下载 2.55 MB；解析、字形处理和换字重排仍需真机量化。
5. **APK 跨域 API 缺少显式预检缓存时间**。本地与公网 OPTIONS 均确认没有 `Access-Control-Max-Age`。在 Authorization 请求较多时，增加网络往返；两个公网协议客户端样本分别约 9.6 秒、10.1 秒，需要排查链路波动。
6. **布局存在压力线索，尚不能直接判为某个组件的根因**。受高宿主机负载影响的追踪中，数据结束后仍有明显渲染等待；应把字体、首页挂载、阅读分页的布局成本拆开验证。

建议先完成观测、儿童首页关键数据瘦身、公网链路定位，再实施字体切片、次要区块延后和 APK 预检缓存。暂不启动原生框架重写，也不更改已确认的 UI 风格、桃 Logo 或字体外观。

## 3. 两端完整加载链

```text
PC：启动 Tauri → 创建 WebView2 → 公网根 HTML → JS/CSS → 恢复会话/判断角色
    → 儿童路由 chunk → 并行家庭校验与当前页面数据 → React 挂载/布局 → 可操作
    → 封面/字体/次要区块继续就绪

APK：启动原生 Activity → 创建 Android WebView → 本地 HTML/JS/CSS/字体
     → 恢复会话/判断角色 → 跨域 OPTIONS（有需要时）+ 公网 API
     → 家庭校验/页面数据 → 挂载/布局 → 可操作 → 公网图片/音频
```

PC 更新检查延后 10 秒，APK 更新检查延后 8 秒，均为异步。没有证据证明它们阻塞了最初首屏，不应作为首轮主要根因。PC 音频后台节流开关用于后台朗读，不能为“优化”随意关闭。

## 4. 实测结果

### 4.1 公网入口波动

导航为 `/`，无家庭登录，390×844，阻止 Service Worker；每轮 cold/warm 共享一个新浏览器上下文。初采浏览器 Chromium 153。TTFB 从导航开始算到响应首字节，包含连接阶段；connect 是其中的连接耗时。

| 位置 | 轮次 | 缓存 | TTFB | connect | FCP |
|---|---:|---|---:|---:|---:|
| 源站 | 1 | 冷 | 100ms | 11ms | 3408ms |
| 源站 | 1 | 暖 | 20ms | 0ms | 448ms |
| 公网 | 1 | 冷 | 8542ms | 7227ms | 13316ms |
| 公网 | 1 | 暖 | 1115ms | 0ms | 2580ms |
| 源站 | 2 | 冷 | 53ms | 4ms | 4860ms |
| 源站 | 2 | 暖 | 1928ms | 0ms | 2804ms |
| 公网 | 2 | 冷 | 1528ms | 534ms | 4156ms |
| 公网 | 2 | 暖 | 691ms | 0ms | 976ms |

慢样本全部保留，包括源站异常暖样本。宿主高负载也会影响浏览器调度，因此这里确认的是“链路有明显波动”，还不能归因到 Cloudflare 某节点、Tunnel、DNS、运营商或源站中的单一环节。

后续公网补测：HTML 200、`Cache-Control: no-cache`、`CF-Cache-Status: DYNAMIC`，TTFB 1795ms，connect 594ms；两份字体完成加载，无页面脚本错误。初采只等待页面就绪后 3.5 秒，公网资源记录中没有已完成字体条目，不代表字体没有请求；补测等待字体就绪后确认了下载。

OPTIONS 协议客户端补测：

| 端点 | 源站 | 公网 | 状态 | Allow-Origin | Max-Age |
|---|---:|---:|---:|---|---|
| `/api/health` | 65ms | 10130ms | 204 | `https://localhost` | 无 |
| `/api/content/books` | 18ms | 9630ms | 204 | `https://localhost` | 无 |

请求使用 `Origin: https://localhost`、GET、Authorization 预检头。它确认了当前响应策略和两个慢样本；它不是在真实 Android WebView 发出的请求，也不是所有 API 预检都必然耗时 10 秒。首次探测公网 OPTIONS 曾发生 socket hang up，随后补测成功，均保留证据。

### 4.2 儿童端隔离压力样本

浏览器 Chrome 155；视口 390×844。弱网条件：CPU 4 倍减速、100ms 延迟、200000 B/s 下行、100000 B/s 上行。`cold-local` 不限速、关闭 HTTP 缓存；`warm-slow` 先预热同一路由。SW 全部禁用。它们是网页实验条件，不是完整 APK 冷启动模型。

ready：主要内容存在，今天页继续阅读按钮可用，再经过两帧；阅读器为正文存在并经过两帧。没有等待所有字体/封面/音频。今天页续读点击旅程本轮未测；长文阅读器执行一次真实翻页及阅读设置点击。

27 个样本无页面脚本错误、无记录到的失败请求。网络资源列表只包含采集时已结束的请求，不能据此保证晚完成资源全部成功。高负载使结果离散，**不计算现场分位数，不据此比较根入口和深链的提速幅度**。

首个根入口样本的时序：

- ChildHome chunk：3392—3896ms；家庭校验与目录：5042ms / 5076ms 开始，已并行。
- 全目录：6392ms 完成；编码体 45475B、解码 JSON 191259B；合成目录 277 本。

- 主按钮 ready：10778ms。目录完成后仍相隔约 4386ms，说明不能把所有等待解释为 API 下载。

该样本导航到 ready 的目标渲染主线程中，Layout 事件区间并集约 2928ms，最大一次约 1795ms；今天页深链约 2240ms；长文阅读器约 963ms。只统计对应主线程并截取到 ready，排除了其他 renderer。不同事件类别存在嵌套，不能把 Layout、FunctionCall、模块执行的时间相加。高负载和 CPU 减速放大了墙钟时间；当前只能支持“需要进一步定位布局成本”，不能断言某个函数造成这些全部耗时。

长文阅读器单次翻页到页码更新后一帧：弱网冷样本约 68—83ms、本地冷约 7—30ms。阅读设置等输入产生的实验 INP 为 72—632ms；它不是现场 INP p75，也不是每次触屏翻页的视觉动画完成时间。

### 5.1 PERF-03 的数据边界

关键 bootstrap 不返回全量书库、所有孩子、章节正文、周报历史或成就明细。复用已有业务规则，而不是另造一套推荐/进度算法。若每日诗等独立请求已经足够快，保留独立返回，不为减少“接口数量”强行合并。

失败恢复：继续读目标失效时呈现可用的推荐/发现入口；请求超时可重试，不能让骨架无限转。后台刷新失败保留当前已验证内容，但身份、孩子归属、访问撤销等安全失败必须按原规则清空/拒绝。任何本地提示都不决定权限。

### 5.2 缓存与服务端边界

公共目录元数据可以按发布修订缓存；家庭屏蔽、孩子进度/收藏、私有书目必须以正确家庭、孩子、身份版本隔离。开书时仍按最新状态校验。改变进度冲突语义、PIN撤销策略或离线访问能力都不是“顺手提速”，必须单独验收。

当前 `listBooks` 中进度→屏蔽→图片→收藏存在多段 await，进度映射还反复 `rows.find`。可在已测DB耗时/CPU证据成立后并行独立查询、用现有Map模式替代查找；SQLite并发不保证吞吐提升，不能只凭Promise改写宣称更快。不要盲加索引，先查查询计划与真实慢段。

### 7.2 拟定性能预算

下列是修复后拟验收的产品目标，**不是本轮测得结果，也不是承诺提速比例**。正常网基准暂定RTT≤100ms、下行≥10Mbps；弱网固定本轮100ms/200KBps条件，真机单独说明型号、内存、系统、WebView、网络和温度。

| 指标 | 正常网目标 p75 / p95 | 弱网目标 p75 / p95 |
|---|---|---|
| 原生进程冷启动→儿童首页主要阅读入口可操作 | APK ≤2.5s / 4s；PC ≤3s / 5s | APK ≤4s / 6s；PC ≤5s / 8s |
| 暖启动或选定孩子→首页可操作 | ≤1s / 2s | ≤2s / 3s |
| 点击开书→正文与恢复位置稳定 | ≤1s / 2s | ≤2s / 3.5s |
| 可见首屏封面完成（与按钮就绪分开统计） | ≤2.5s / 4s | ≤4s / 6s |
| 已有音频缓存：点击→真实发声 | ≤1s / 2s | ≤2s / 3s |
| 新合成：点击→真实发声 | 先独立建立供应商基线，再确定SLO；不能套用缓存目标 | 同左，必须有取消、局部错误及可恢复等待 |
| 翻页输入→下一帧响应 | ≤100ms / 200ms | 同左，弱网不应让已加载正文翻页再次等网络 |

核心数据预算：今天页关键读取≤2次、关键响应解码≤40KB；发现/家庭书架每页有明确上限；首屏字体候选≤300KB；JS/CSS不因优化反向膨胀。另记录LCP、CLS、INP原始数据，不能用LCP替代“可操作”或用一次点击代替整段现场INP。

分位数必须来自足量、分层的有效样本。受控每端/网络/冷暖候选至少交替30次并保留全部样本、失败及异常背景负载；现场每主要分组先积累至少200条，报告样本量和分布，稀疏分组继续积累。小样本不对外宣称p95达标。全量总体数值不能掩盖低端安卓或弱网分组。

### 7.3 功能与对抗验收矩阵

- PC安装版：全新WebView2缓存、暖缓存、重启进程、切角色、断网/恢复、升级；最小化/锁屏听读30分钟跨章。
- Android APK：至少一台低端与一台常用机，记录实际WebView；本地静态加载、公网API、Wi-Fi/移动网、覆盖升级、杀进程恢复、后台播放与省电策略。
- 儿童旅程：登录→选择孩子→今天→继续阅读→退出→续读；发现页多次下滑/搜索/切条件/收藏；家庭书架→详情→图文长章→听读→跨章。
- 规模：空库、小库、277本及更大合成库；空进度/大量进度、多个孩子、缺图、慢图、字体加载失败、目录版本变化、旧chunk404。
- 一致性：返回滚动位置、字号/行距/横竖屏/日夜模式、图片和字体晚到、分页锚点、首尾页、进度冲突、并发设备。
- 权限：切家庭/孩子不闪现前一个孩子的数据；家长屏蔽、课程下线/未启用、PIN撤销、票据过期、退出登录后的请求均遵循现行规则。请求取消后旧响应不能覆盖新身份。
- 故障：API 401/403/409/429/5xx、超时、断网、损坏音频；主要入口不无限禁用，模块局部可重试，不自动无限重试或触发额外付费生成。
- 视觉：390/768/1440宽度与日夜模式对照，字体与Logo、儿童风格保持，必要布局调整留对比截图。不能通过隐藏内容、删字体、牺牲可访问性来取得“提速”。
