# 桃阅读 UI / UX / UE 专项评估与升级方案

日期：2026-10-02。关联：`36-整体升级评估与迭代方案-2026-10-02.md`。评估基线 HEAD `37c8a34`。本次仅评估和规划，不修改业务代码。

## 1. 结论

桃阅读当前“纸张底色、桃子品牌、贴纸卡片”的方向有辨识度，适合家庭与儿童场景；需要优先升级的是视觉层级、任务排序、阅读界面结构和交互一致性。

**当前最明显的体验瓶颈是：页面壳层重复、阅读控件在手机上挤压、关键操作藏在横滑区、首次状态缺乏有效行动、筛选状态与真实效果不一致、家长任务被统计和家庭码挤到下方。**

不建议先全站换皮。建议保留品牌，按“阅读主干优先 → 找书与首次使用 → 家长任务 → 通用组件与状态”推进设计升级。

## 2. 方法、证据与边界

UI 指视觉呈现与界面系统；UX 指完成任务的流程、信息架构和认知成本；本文将 UE 用于操作过程中的可用性、反馈、容错、无障碍与设备适配。UX 与 UE 有重叠，分类仅为便于组织任务。

证据分级：

- **B：当前浏览器观察。** 线上公开登录页；本地同版本独立演示环境的选人、今天、发现、书籍详情、阅读器、阅读设置、家长今天与内容中心。手机 390×844，阅读设置平板 768×1024，家长今天与内容中心桌面 1440×900。
- **C：当前代码确认。** `v8.css`、`V8App.tsx`、`ReaderPage.tsx`、`FamilyTrialPages.tsx`、`LoginPage.tsx`、`ParentHome.tsx`、家长内容/设置模块、共享弹层。
- **H：历史说明。** `design-system.md` 与历次 UI 报告，仅用于识别演变和规范偏差，不能证明当前达标。
- **V：尚待验证。** 实际儿童/家长任务观察、真触屏长按与滚动、Safari/软键盘、全量页面状态、音频连续性和辅助技术。

## 3. 第一性原理：什么界面才适合桃阅读

1. 阅读内容是主体；控件和品牌应在需要时出现，不长期争夺视线。
2. 不会熟练阅读的孩子不能只依赖文字菜单、隐形手势和横滑发现操作。
3. 家长的价值在快速理解“现在读什么、怎么陪”，不是先看运营式数据面板。
4. 每个界面应有一个明确主任务；功能多不意味着都应进入一级导航。
5. 视觉状态必须可信：选中、暂停、已保存、读过、读完、加载失败都对应真实状态。
6. 同一产品在不同书源、设备、角色下，基本操作语言要一致，但儿童与家长的信息密度可不同。
7. 精致感来自有序层级、排版与反馈，不来自持续叠加粗描边、阴影、旋转、彩色贴纸。

## 4. 已有优点应保留

- 桃子图标、暖纸色、黄色主按钮、黑色线条已形成品牌线索。
- 手机书架两列、桌面侧栏与内容区具备基础响应式结构。
- 封面优先的找书方式对孩子比纯文字目录更友好。
- 阅读主题、字号、字体、行距、音频设置已有能力；无需重新建设所有功能。
- 阅读器弹层已有首焦点、Tab 循环、Escape 和关闭后焦点恢复实现，不应把它描述成“完全没有无障碍”。
- 部分筛选与选择项已有 `aria-pressed`，已有跳过导航、安静模式、错误重试等基础。

## 6. 页面升级方案

### 6.1 登录和选人

登录首屏包含品牌、一句具体价值、清晰的加入/创建/示例三种任务。角色选择表达权限和使用场景，不用“谁讲故事”隐喻代替实际动作。家长门属于误触防护，设计不宣称其具有身份安全保证。

选人卡保留大触达；头像可用不同颜色/图案而非同一个“昵称首字”，本次小桃/小柚都显示“小”，低龄区分度不足。换人入口放可识别头像与名字，先停止当前音频再切换。

状态覆盖：首次、已有家庭、码错误、限流、网络故障、会话过期、隐私存储不可用；错误紧邻字段，保留已输入内容，并给明确恢复路径。

### 6.2 孩子今天

推荐结构：问候/头像 → 一张继续读或首次开始卡 → 2–3个精选封面 → 可选主题 → 家庭记忆。纸书/家庭书放适当的次级入口。今天页面不承担全部功能的菜单总览。

继续卡明确书名、章节、恢复位置，主行动“继续读”；无进度时主行动“挑一本开始”，按钮直接进入找书或打开推荐。不要空标题配两颗禁用按钮。

手机首次视口至少能识别一个具体内容与有效主行动；英文长标题、无推荐、只有一推荐、全屏蔽情况单独设计。

### 6.3 找书与书卡

搜索、语言、主题各有清晰职责；统一可组合筛选规则。主题选中后保持搜索与语言语义一致，若互斥必须明确撤销而非偷偷失效。显示结果数、已选条件、清除按钮。

默认减少筛选行，仅显示常用主题与“更多”；横滑区有截断/渐隐/箭头等可发现线索，不能靠隐藏滚动条暗示。加载用结构化占位，错误显示重试，无结果建议清除筛选。

书卡：封面不再承载多层小文字；书名1–2行、辅助信息一行、阅读进度一条；收藏心形/星形加明确可访问名称与已收藏态，避免“+”被误认为添加/展开。

### 6.4 书籍详情

只使用一层品牌壳。上半区：封面、书名、作者/加工方式、简短介绍；主按钮开始/继续读，试听和收藏次级。读法/篇幅/来源信息按需要展开。章节目录未读/在读/已读状态有真实依据。

“适合一起读”“建议年龄”“大约多久”分别回答实际问题，不增加内部设计哲学长文。内容来源与AI说明保留，但不能挤占开始阅读主动作。

### 6.5 阅读器

使用独立阅读布局，全视口高度；顶部返回+书名/章节+目录/更多，正文一个滚动区。手机标题省略可以，但按钮不收缩到无法点击；阅读中不保留全站侧栏、品牌栏和找故事按钮。

默认底条只保留主听读操作和一个设置入口；正在听时显示播放/暂停、上一段/下一段及简洁进度，更多进音频面板。字号进入排版面板，减少主条宽度。所有高频按钮无需横滑才能发现。

正文按文类排版：故事段落、诗句、拼音、译注、图片各有规范。低龄字词密度、英文长词、最大字号、图注和夜间高亮都要专门验收。保留图片放大，但同时提供键盘可操作入口。

专注模式用显式开关与可靠退出；正文留白手势只是快捷补充。保存失败在阅读中持久显示“未同步/重试”，不靠短暂toast承担数据安全反馈。

收尾：正文结束可见主按钮，主底条不必常驻强提醒；中途结束允许直接保存与退出。理解/识字活动可选，先修正评估语义，不强迫孩子测试。

### 6.6 设置、目录与弹层

排版和听读分面板；常用项优先，音色折叠为当前音色+选择列表。标题固定、关闭始终可见，底部安全区留足。设置直接生效并明确是否设备级/孩子级。

公共弹层契约：具名dialog、初始焦点、Tab圈定、Escape可关闭（确实不可关闭的流程明确说明）、背景inert/不可交互、锁定背景滚动、关闭恢复焦点。手机使用底部面板或全屏，平板/桌面使用对话框；不能一套fixed定位在所有尺寸硬撑。

### 6.7 我的与家庭书

我的先显示当前在读与记忆，再进入收藏、读完、生词、划线/书签；不把速测放成能力评判入口。tabs使用完整语义，或采用更简单的按钮导航，不为语义标签本身增加错误。

公共书与家庭书都能继续读，但来源/私有状态明确。家庭书的无封面、长标题、导入中、导入失败、无可读章节与已删除状态单独处理。阅读器行为按同一规范验收。

### 6.8 家长今天、内容、足迹、设置

今天：孩子当前阅读卡和一条可用陪读提示在前，家庭统计简短摘要，邀请设备为次要入口。无活动时允许家长直接为孩子选书/记录纸书，不只要求到另一个设备找不存在的按钮。

内容：公共书、家庭书、外部来源、纸书入口保留，但在手机避免多级横滑叠加。筛选、排序、每孩状态和管理操作分层；屏蔽/删除/重新解析动作区分影响并在确认中具体说明。

足迹：先看书与记忆，再数字；支持按孩子和时间回看。周报通知只代表真实的新报告状态，不是每次进入都必须看。分享先预览再主动导出。

设置：分阅读偏好、家庭成员/设备、来源绑定、数据/隐私；危险操作在独立区，保存状态和局部错误可见，不能失败后隐藏整张卡。

家长端保持同品牌，但减少旋转、大彩块和多层气泡，让信息更清楚。家长不需要被儿童语气包围，儿童也不需要读成人数据面板。

## 7. 设计系统升级规格（提议，实施时定稿）

| 项目 | 建议规范 | 注意 |
|---|---|---|
| 品牌 | 保留暖纸底/桃子/黄色主行动/深墨字 | 不增加无依据“护眼保护”功效承诺 |
| 语义色 | 主行动、选中、成功、警告、错误分别有语义token | 不只用颜色表达状态 |
| 字号 | 正文16–18px起；儿童主行动16–18px；辅助说明14px起；阅读18–30px可调 | 最终按真实字体与设备验证；装饰文字可更小但不承载信息 |
| 对比 | 普通文字4.5:1，大文字3:1；必要控件边界/焦点3:1 | 不把触达尺寸与WCAG规范混同 |
| 触达 | 儿童主行动56–64px高；常用次级48px；图标目标至少44×44px；家长主操作48px | 产品目标，不称为WCAG统一最低值；窄宽按钮也必须满足宽度 |
| 间距 | 4px基数；手机边距16–20px；按钮间8–12px | 拥挤问题先降低数量，不能只缩小尺寸 |
| 层级 | 正文卡轻边界；主卡/主按钮保留贴纸阴影 | 重点不是每个组件都高对比描边 |
| 阅读布局 | 顶部轻控制、正文单滚动、底部高频可见 | 安全区、横屏、软键盘分别验证 |
| 反馈 | 正在做/成功/失败/待同步各自明确 | toast只处理低风险短反馈 |
| 动效 | 150–250ms微反馈；可减少；无操作阻塞 | 安静模式与系统减少动效同时支持，含smooth scroll |
| 组件 | Button/Card/BookCard/Filter/Tab/Dialog/Toast/Field/Empty/Error/Loading统一变体 | 替换按任务逐步进行，避免全量CSS重写 |

现有旧规范需归档为历史版，再发布对应当前界面的设计系统；明确组件状态、按钮主次、字体回退、焦点样式、适配断点与例外。

## 8. 验证计划与完成标准

### 8.1 用户任务验证

建议先做方向性小样本：3–5岁、6–8岁、9–12岁各2–3个家庭，监护人陪同；先由家长决定是否参与。任务记录采用匿名编号，不收集儿童照片、声音或真实身份。样本用于找问题，不证明学习效果。

任务：首次开始一本、继续昨天的书、找英文/某主题、暂停与恢复朗读、放大图片、结束并回主页、换孩子、家长找到共读提示、纸书记录、取消危险操作。

记录成功/协助/失败、误触、犹豫点、操作次数与反馈理解。禁止把“完成不了”归因于孩子不配合；先观察界面与说明是否合理。

### 8.2 屏幕与输入矩阵

- 360/390/430px手机；768/1024px平板；1280/1440px桌面；手机横屏短视口。
- 真实iPhone/iPad Safari、Android Chrome和桌面；鼠标模拟无法证明触屏手势可用。
- 200%缩放、最大字号、长中英文标题、低速/离线/接口500/媒体404、存储不可用。
- 键盘全流程、焦点可见、读屏控件名称与状态、减少动效、安全区和软键盘。

### 8.3 页面状态矩阵

每个核心页面覆盖首用/加载/正常/空/错误/重试；每个可写动作覆盖提交中/成功/失败/重复操作。推荐不足、筛选全空、音频不可用、进度冲突、内容下架、孩子删除、会话过期作为专项。

### 8.4 发布门槛

1. 手机阅读顶部不换行挤压，关键控件达到约定触达；主听读与退出/收尾均可明确发现。
2. 无首次空卡配不可点主按钮；每页有真实可执行的主行动。
3. 筛选状态和数据一致，加载/错误不假装无结果。
4. 详情不重复品牌壳；阅读页无不必要全站导航，滚动结构明确。
5. 正常文字色符合约定对比度，复杂图片上的叠字可读。
6. 弹层无焦点逃逸/背景交互，关闭与恢复可操作；隐藏控件不进入Tab序列。
7. 两种书源阅读交互一致；真设备音频与长按另有记录。
8. 设计任务交付含前后截图、状态矩阵与操作证据；仅“截图漂亮”不能验收。

## 9. 与整体升级排期的合并

不额外叠加另一套全站重构工期。将U01–U04、U13等核心问题纳入docs/36的T02/T06/T10；U25纳入T09；家长层级纳入T11；设计规范纳入T15。

建议设计工作顺序：

1. **D0：状态与流程稿。** 先定义首用、在读、错误和退出；建立五张关键线框（登录、今天、发现、阅读、家长今天）。

4. **D3：家长端与设计收敛。** 共读任务优先、内容管理、回顾和设置；更新设计系统。
5. **D4：真实用户与设备复核。** 根据观察修正，不先承诺全部新设计一定更好。
