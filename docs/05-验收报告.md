## 3. 质量过程（对抗式审查协议执行情况）

- **三道门**贯穿全部 11 个工作夜：Gate A（verify 全绿）+ Gate B（code-reviewer 对抗审查，P0/P1 当夜修复并复审闭环）+ Gate C（验收清单走查 + 截图 + 回归抽查）。
- 累计登记缺陷 **54 项**（bug-register.md），其中 P0×1（密钥出库，已彻底处置并清洗历史）、P1×17（全部当夜清零）、其余 P2/P3 全部处置（fixed / wont-fix 带理由 / 带计划夜次）。
- 交付日马拉松（诚实披露）：全库两轮终审子代理因模型限流三次中断（810s/1142s 后失败），降级为「交付日新增代码聚焦审查」（完成：demo/搜索/金句星球/e2e 配置，发现 P1×1 + P2×8，全部当日修复，明细 N11-001~009）+ 存量代码依赖逐夜审查证据。
- 有代表性的事件：第 2 夜对抗审查捕获真实 API key 误入测试源码——换假 key + `git filter-branch` 清洗全部历史 + 建议轮换；第 6 夜真实数据暴露两个 mock 臆测缺陷（类目白名单口径、孩子视图字段名）——修正并固化「mock 必须来自实测回包」为协议教训。
