1. **模拟器验证受阻（宿主 OS 问题非代码问题）**：本机 Windows Insider 26220 下 WHPX 声明可用但
   qemu 三次静默崩溃（-gpu swiftshader_indirect/-Vulkan 与 -gpu off 两种配置、日志均止于
   「WHPX operational」）。尝试链已记录；下轮在非 Insider 稳定版或真机直接验。
   **因此 M2a 断网冷启、M2b 息屏连播、M2d 杀进程提醒三项验收门未过真机验证**——代码已交付、
   静态与浏览器侧验证全绿，真机行为属人工门。
2. **真机门（用户 10 分钟清单，APK 0.1.7 已可侧载）**：
   ① 断网冷启：开飞行模式点 App → 应见登录页/离线书架而非白屏
   ② 息屏连播：联网进书开朗读 → 息屏 5 分钟 → 应继续有声；锁屏通知可暂停/续播
   ③ 来电让声：播放中拨打电话 → 应自动暂停；挂断后手动恢复
   ④ 离线听读：详情页「保存图文与已有朗读」→ 飞行模式 → 离线书架读+亮屏听

## 6. 对抗审查（11-06 追记：六缺陷修复，APK 0.1.8）

审查方法：原生生命周期/竞态/事件语义三面清单 + 两条证据侦查（dl 域 CORS=* ✓；
segment-update=冷合成「直播流→缓存 URL+时间轴」模式，原生追加的 live URL 即完整音频、
时间轴经队列对象流到高亮轮询——判定非缺陷）。修复六项：

| # | 缺陷 | 修复 |
|---|---|---|
| A | startForegroundService 启动服务但媒体通知 5s 内未挂起（网络慢缓冲>5s）→ ForegroundServiceDidNotStartInTimeException 崩溃 | 改 startService（播放总在前台手势路径）；前台态由 media3 开播时接管 |
| B | stopAll() 内 stopSelf：web 的 stop()→speak() 同步连发，append 落进正在销毁的服务=静默死 | 服务常驻不自杀（媒体 App 标准形态），前台态由 media3 管理 |
| C | 渐弱定时器不可作废：哄睡中途点新播放→旧定时器停掉新队列+音量留 0（静音 bug） | fadeToken 代次作废 + append/play/stopAll 均恢复音量 1 |
| D | 暂停态映射错：`playing=playing||(…)` 暂停时 playing 恒真；原生缓冲期 isPlaying=false 会误发暂停 | 原生 emitPlayState=playWhenReady&&(READY\|BUFFERING)（去抖）；web 直接采信 |
| E | 末段错误无「下一段」→ web 卡死播放中 | 错误在末段时补发 ended |
| F | NATIVE_NARRATION 模块求值时常量判定：桥注入晚于模块求值→APK 内静默回退浏览器引擎（息屏断播复活） | 改 nativeNarrationActive() 每次即时判定；浏览器构建短路零成本 |
| + | M2d 提醒草稿未初始化：已设提醒后重进设置页点「开启」误报格式错 | 草稿初始值=已存提醒 |
