## 1. 总原则

1. **日志驱动，夜夜自愈**：`nightly-log.md` 是唯一进度事实源。每夜开工先读日志确定状态：该夜完成则顺延做下一夜；有欠账先补欠账；任何一夜中断，后续夜自动接续，不重复、不跳过。
2. **夜次规则**：夜次 = 当天日期 − 9 月 3 日（9/4 = 第 1 夜，…，9/19 = 第 16 夜）。
3. **跑满时段**：23:00 开工；07:30 后不再开新任务，进入收尾（审查门 + 日志 + 提交）；08:00 前必须完成收尾。
4. **质量不降级，范围可裁剪**：任何一夜不得为赶进度跳过三道审查门；进度落后时按 §6 裁剪顺序砍范围，保底交付线 = 核心闭环（孩子端仪式流 + 家长端共读卡/周报）+ 零已知缺陷。
5. **Phase 0 的诚实说明**：原计划的 5 家庭访谈需用户本人参与，夜间会话无法执行；以「技术三验（deepLink 链路/网关限频/听书跳转）+ 创始人家庭 dogfood」替代，访谈留给白班用户随时补充，结论记入日志。

## 3. 每夜详细计划

> 每夜格式：目标 / 任务（按序执行）/ 验收清单（= 审查协议 Gate C 走查项）/ 对抗审查重点。任务完成的定义：代码 + 测试 + 文档同步 + 提交。

### 第 1 夜（9/4）— 工程基建
- **目标**：仓库与地基。白班已启动（见日志），夜班补齐收尾。
- **任务**：① lint 基线（eslint flat config，`npm run verify` = typecheck + lint + test）；② 网关真机连通性冒烟脚本（`npm run smoke:weread`，读 `.env` 的 `WEREAD_API_KEY`，调用 `/_list`、`/shelf/sync`、`/readdata/detail`，输出体检报告，网关异常不阻塞）；③ 技术三验之二：网关限频摸底（连续 50 次 `search`，记录 429/延迟曲线，结论写入日志供缓存与限流参数校准）。
- **验收**：`npm run verify` 全绿；冒烟报告落盘 `docs/reports/night-01-smoke.md`。
- **审查重点**：网关适配层（重试/超时/upgrade_info/errcode 分支）、密钥加密。

### 第 2 夜（9/5）— 数据层与家庭 API
- **任务**：① Prisma + SQLite 落地 [02 §4.4] 全部 10 张表 + 迁移；② 家庭码/设备绑定认证（family_code + device_token，内存态签名 JWT）；③ `POST /api/family`（创建）、`POST /api/family/:id/bind-weread`（key 加密入库，回显仅尾 4 位）、child_profile CRUD；④ 单测。
- **验收**：迁移可从零库重建；认证中间件缺 token/错 token 均 401；key 落库为密文、接口不回显全文。
- **审查重点**：认证绕过、越权（family A 不可读 family B）、key 泄漏路径（日志/回显/错误信息）。

### 第 3 夜（9/6）— 微信读书业务 API
- **任务**：① `/api/shelf`（书架聚合：books+albums+mp，含"书架数量=三者和"口径）② `/api/book/:id/info|chapters|progress` ③ `/api/book/recommend`（童书类目白名单过滤，家长可屏蔽单书）④ `/api/book/:id/bestbookmarks`；全部走 WereadService 缓存与限流。
- **验收**：用 mock 网关数据联调通过；缓存命中（第二次调用 0 出网）；限流触发返回 429 语义化中文提示。
- **审查重点**：缓存键按家庭隔离；对微信读书回包字段不做臆测解释（对照 skill 文档）；类目过滤白名单不含成人类目。

### 第 4 夜（9/7）— 共读域 API 与模板共读卡
- **任务**：① cosession（开/收尾/进度三档/心情/金句）② highlight_star（口述录入 + 热门划线点选两来源）③ achievement（夜灯/最长连续/读完，纪念式，无兑换）④ 模板版共读卡生成（基于书信息+热门划线+年龄段三档问题梯度 [02 §2.2]）⑤ 单测。
- **验收**：一次完整共读（开→选书→收尾）落库正确；断线续传（重复收尾幂等）；成就只在阈值跨越瞬间解锁一次。
- **审查重点**：幂等性、时区（一律存 Unix 秒）、成就重复解锁竞态。

### 第 5 夜（9/8）— Web 地基与设计系统
- **任务**：① apps/web：Vite+React18+TS+Tailwind+PWA（vite-plugin-pwa）+ Framer Motion；② 设计系统（[design-system.md](./design-system.md) 同步落盘）：夜空蓝→桃粉渐变主视觉、大圆角、大按钮（≥64px 触达）、月亮/星星/云朵 SVG 素材、日夜双主题（孩子端固定"夜空"）；③ 基础组件：TaButton/TaCard/TaSheet/TaSticker/Loading/ErrorState/EmptyState；④ 路由与角色框架（孩子端/家长端切换 + 家庭码登录）；⑤ 视觉走查截图基线。
- **验收**：组件 demo 页（/dev/kitchen-sink）截图对比设计稿；Lighthouse PWA 可安装；冷启动 <2s。
- **审查重点**：可访问性（对比度 ≥4.5、字号 ≥16px、触达面积）、动画在低端安卓降级（prefers-reduced-motion）。

### 第 6 夜（9/9）— 孩子端 M1-M2：仪式入口与选书
- **任务**：① 月亮升起入口（睡前时段唤醒 + 随时点亮）；② 「今晚读什么」：继续读（进度文案）／今晚推荐 3 册／翻书架／骰子随机；③ 选书交互动画（翻卡/星光反馈）。
- **验收**：从入口到选定一册 ≤60 秒（走查计时）；空书架/接口失败均有友好态；点击即有反馈（无死寂）。
- **审查重点**：空态与错误态覆盖、动画不阻塞交互、按钮防连点。

### 第 7 夜（9/10）— 孩子端 M3-M4：出发与收尾
- **任务**：① 出发卡（书封+deepLink 唤起微信读书/纸质书/听书三通道 + 3-2-1 出发动画）；② deepLink 降级链（未装 App→Web 版兜底 + 引导浮层）；③ 收尾流：进度三档、心情贴纸、金句（口述录入 + 从热门划线点选，显示「N 人划过这句」）；④ 技术三验之一落地：真机 deepLink 三链路实测记录（无法真机的链路以 mock 验证 + 风险标注）。
- **验收**：三条出发通道全可用（至少 mock 级验证）；返回应用后状态保持；金句两来源均落库。
- **审查重点**：deepLink 只用回包原值（禁止自行拼接）、会话中断恢复、双击/连点幂等。

### 第 8 夜（9/11）— 夜灯成就墙 + 护眼限制
- **任务**：① 夜灯墙（第 N 晚亮灯、点亮动画、最长连续纪录、读完的书）；② 孩子端会话软封顶 5 分钟（超时进入「月亮睡了」收尾并锁定至次日晚间时段）；③ 21:30 后自动睡觉模式；④ 家长端框架（Tab：今晚/书架/周报/设置）。
- **验收**：封顶与睡觉模式可测（注入时钟）；解锁瞬间有仪式感动画且只播一次；锁定期间入口文案友好不惩罚。
- **审查重点**：客户端时钟不可信（服务端校验时段）、成就数据与 cosession 一致性。

### 第 9 夜（9/12）— 家长端核心
- **任务**：① 绑定向导（获取 API Key 引导图文化，key 只输一次）；② 家庭书架（书/专辑/文章收藏三分区 + 屏蔽管理）；③ 今晚共读卡页（模板版全量 UI）；④ 设置（睡前时段/软限时长/类目偏好/注销家庭=数据一键抹除）。
- **验收**：家长 5 分钟内完成从安装到看到共读卡的全流程（走查计时）；注销后库内数据物理删除且日志无残留。
- **审查重点**：注销删除完整性（含备份表/缓存）、设置项边界校验、家长端操作对未收尾共读的影响。

### 第 10 夜（9/13）— 周报与分享卡
- **任务**：① 服务端周日汇总任务（node-cron 周日 19:00，聚合自采共读数据 + `/readdata/detail` 对照）；② 家长周报页（共读 N 晚/累计分钟/书目/金句回顾/下周建议）；③ 分享卡 PNG 生成（服务端 canvas/SVG→PNG，无第三方上传）；④ 首页「本周足迹」摘要条。
- **验收**：任选历史周可重生成周报；分享卡 1080×1440 规格、无隐私字段（不含 key/家庭码/孩子真名）；空周优雅展示。
- **审查重点**：周边界时区（本地周一起点）、统计口径与 [notes.md 口径] 一致、分享图字体版权（用系统/开源字体）。

### 第 11 夜（9/14）— 端到端与性能
- **任务**：① Playwright e2e：完整夜流（登录→仪式→选书→出发→收尾→成就→周报）+ 家长流；② 演示数据种子（demo 家庭 + mock 网关录制回放，无真实 key 也能全功能演示）；③ PWA 离线壳（断网可看夜灯墙/最近共读）；④ 性能：冷启动 <2s、动画 60fps（低端档 30fps 可接受）、接口 P95 <300ms（本地）。
- **验收**：e2e 全绿且可在 CI 重跑；`npm run demo` 一键起演示环境；Lighthouse ≥90（Perf/PWA）。
- **审查重点**：e2e 稳定性（重跑 3 次零 flaky）、种子数据不混入真实家庭、mock 与真实回包结构对齐（用第 1 夜录制的真实样本）。

### 第 12 夜（9/15）— 金句星球与搜索选书
- **任务**：① 金句星球（全书热门划线瀑布流 + 划线下想法精选 `/book/readreviews`，内容经适龄过滤）；② 搜索选书（`/store/search`，孩子端大键盘 + 可选语音）；③ 共读卡增强：若运行环境具备 LLM 接口则接入生成讲述要点/提问（模板永远兜底），否则纯模板增强版。
- **验收**：搜索含中文关键词往返正确（UTF-8 回归）；金句星球无成人类目内容渗漏；共读卡在无 LLM 时退化为模板且无报错。
- **审查重点**：外部内容适龄过滤（关键词+类目双闸）、LLM 输出安全兜底（长度/敏感词/失败降级）。

### 第 13 夜（9/16）— 对抗式审查马拉松 Ⅰ（全库）
- **任务**：按 [04 协议] Gate B 对 **server + shared 全量代码** 分模块派 code-reviewer 子代理轮扫（网关/认证/数据/业务路由/定时任务/密钥）；P0/P1 当夜清零，P2 入登记册；回归全量测试。
- **验收**：每模块出具审查报告（发现→修复→复验闭环记录于日志）；`npm run verify` + e2e 全绿。
- **审查重点**：见协议宪章；重点补「并发竞态、事务边界、Prisma 注入面、限流公平性」。

### 第 14 夜（9/17）— 视觉打磨马拉松
- **任务**：① 全页面截图走查回路（每页 PC/平板/手机三档 → 缺陷清单 → 修复 → 复拍）至全部达标；② 微交互与仪式感细节（按钮触感、页面转场、夜灯点亮、出发倒计时）；③ 主题一致性（色彩/圆角/间距/字体阶梯逐一对照 design-system.md）；④ 动画性能复核。
- **验收**：关键页（入口/选书/出发/收尾/夜灯/周报/设置）三档截图全部达标入 `docs/screenshots/night-14/`；无布局破碎、无截断文案、无对比度违规。
- **审查重点**：文案语感（正向、无焦虑话术，对照 [01 §7.3] 与负向清单）、孩子端无任何可点击广告位/外链。

### 第 15 夜（9/18）— 对抗式审查马拉松 Ⅱ + 交付准备
- **任务**：① web 全量 + e2e 场景的对抗轮扫（状态死角/竞态点击/离线/时钟边界/超长文本）；② bug-register 全部 P2 处置完毕（修复或明确「不修理由」）；③ README（架构图/快速开始/演示账号）、部署文档、`docs/05-验收报告.md` 初稿；④ 演示数据复核 + 演示脚本（10 分钟走查剧本）。
- **验收**：缺陷登记册清零或全部有处置结论；重装到演示全流程 ≤10 分钟（计时装机走查）。
- **审查重点**：回归（修复是否引入新问题）、文档与实际行为一致性。

### 第 16 夜（9/19）— 冻结与交付
- **任务**：① 全量回归三连跑（verify + e2e + 演示脚本）；② 零缺陷扫尾；③ `git tag v1.0.0`；④ 验收报告定稿（功能清单/指标实测/已知限制/演示指引）；⑤ 交付清单打包（仓库 + 演示模式 + 报告索引）。
- **验收**：三连跑零失败；验收报告数据与实测一致；工作区干净（无未提交文件）。
- **审查重点**：最终状态与报告声称一致（报告即承诺）。

## 4. 每夜固定收尾（07:30–08:00）

1. 三道门结果写入 `nightly-log.md`（当夜状态/完成/顺延或砍掉的任务及原因/审查发现与修复/指标）；
2. `docs/bug-register.md` 增量更新；
3. `git commit`（含日志与登记册）；里程碑夜打 tag；
4. 为下一夜留「交接便签」（下一步最优先的三件事）。

## 5. 不变约束（任何一夜不得违反）

- [02 §3.4 负向清单]：无正文展示、无积分商城、无断签惩罚、无面向孩子的推送、无广告。
- 密钥红线：`.env` 永不入库；key 密文落库、日志脱敏、前端只见尾 4 位。
- 文案红线：正向表达，禁「落后/差距/别输在起跑线」类话术。
- 每夜必须过三道门才允许收夜；任何门失败 → 修复优先于新功能。
