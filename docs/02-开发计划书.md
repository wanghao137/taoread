## 0. 摘要

用 20 周分五个阶段，把调研报告推导出的定位——**"家庭的睡前共读仪式 App：寄生在家长微信读书数据之上的伴读层"**——从纸面原型做到内测 V1。

- **Phase 0（W1-2）验证**：5 个家庭访谈 + 交互原型，验证"睡前选书仪式 + 共读脚手架"假设；
- **Phase 1（W3-8）MVP**：孩子端仪式流（选书→出发→收尾）、家长端周报、微信读书网关适配层，先服务自己家；
- **Phase 2（W9-12）内测**：5-10 个亲友家庭 BYOK 接入，数据驱动迭代激励设计；
- **Phase 3（W13-20）V1**：成就系统、纸质书模式、周报分享卡、合规加固，评估小程序化与商业化路径；
- **每阶段设 Go/No-Go 门槛**，不达标即止损或转向，避免"为做而做"。

北极星指标：**孩子每周自主发起共读的次数**。反指标（不许恶化）：孩子端单次屏幕时长、家长每周维护成本。

## 1. 产品定义（从调研结论推导）

### 1.1 一句话定义

> 桃阅读是家庭的睡前共读仪式应用：孩子在"今晚读什么"里选书，家长拿到"讲什么、问什么"的脚手架，共读时光与金句被收藏，全家每周看见自己的阅读足迹。阅读本身发生在微信读书（deepLink 跳转）或纸质书里。

### 1.2 目标用户

| 角色 | 定义 | 核心诉求（来自调研 §2.4） |
|------|------|--------------------------|
| 孩子（用户） | 3-10 岁，分 3-5 / 6-8 / 9-12 三段，MVP 主打 4-8 岁 | 选书权、完成感、和爸妈在一起 |
| 家长（客户/管理员） | 25-40 岁，微信读书用户，认同共读价值但时间穷 | 省时间（脚手架）、看见价值（周报）、不焦虑 |

**ICP（初始用户画像）= 创始人自己的家庭**（调研 §7.1：书架实测为童书+听书+睡前故事在读）。Phase 1 的交付标准是"自己家连续用满 4 周"。

### 1.3 场景聚焦

只做一个场景：**睡前 30 分钟**（调研 P2 推论：共读是低龄段绝对主场景）。碎片场景（通勤、周末白天）一律不进 MVP。

### 1.4 北极星与护栏指标

| 类型 | 指标 | MVP 目标 | 定义 |
|------|------|----------|------|
| 北极星 | 孩子周自主发起共读次数 | ≥3 次/周 | 孩子端点击"开始今晚的阅读"且完成 ≥10 分钟共读 |
| 北极星 | 4 周共读留存率 | ≥60% | 连续 4 周每周 ≥1 次共读的家庭比例 |
| 护栏 | 孩子端单次会话时长 | ≤5 分钟 | 仪式环节屏幕时间（阅读本身不计入） |
| 护栏 | 家长每周维护时间 | ≤15 分钟 | 设置/管理类操作总时长（埋点） |
| 护栏 | 阅读发生地跳转成功率 | ≥80% | deepLink 唤起微信读书成功率（埋点） |

### 1.5 产品原则（全团队对齐用，评审时逐条对照）

1. **孩子利益优先**：不做焦虑营销，不用"落后/差距"话术；文案全部正向。
2. **激励投联结与胜任，不投物质**（调研 §2.2 过度合理化结论）：成就=纪念册式（"第 100 个夜晚"），不设积分商城、不设实物兑换、不做连续打卡断签惩罚（断签机制被证明制造焦虑并诱发作弊）。
3. **孩子端屏幕时间最小化**（P5）：桃阅读的交互止于"仪式"，长时长的阅读在微信读书/纸质书中发生。
4. **家长减负不减参与**（P3）：自动化一切能自动化的（同步/统计/周报），脚手架化一切需要家长判断的（共读卡），但绝不用"AI 陪读"替代家长本人。
5. **数据自持与最小化**：儿童不注册、不留身份信息；共读记录存自有数据库；API Key 服务端加密托管，永不下发前端。

## 2. 核心体验设计

### 2.1 孩子端：睡前仪式流（主流程，M1-M5）

```
M1 入口（30 秒）
 └ 晚上固定时间（家长设定，如 20:30），孩子端变成"月亮升起"的仪式界面
   —— 或孩子随时主动点亮月亮（北极星行为的入口）
M2 选书（≤1 分钟）
 └ "今晚读什么？"——从家庭书架/上次未读完/今晚推荐 中选一册
   · 上次的书显示进度（"读到小豆豆转学那段啦" ← /book/getprogress）
   · 今晚推荐 3 册（/book/recommend + 童书过滤 + 家庭偏好）
   · 孩子可以"掷骰子"随机，也可以自己翻书架（自主感，P4）
M3 出发（10 秒）
 └ 生成"出发卡"：书封 + deepLink [去微信读书读] / [今晚读纸质书] / [听书模式]
   · 跳转被包装成仪式："3、2、1，出发！"倒计时后拉起微信读书
   · 家长端同时收到今晚的【共读卡】（见 2.2）
M4 收尾（≤2 分钟）
 └回到桃阅读（从微信读书返回/手动回来）："今晚读到哪儿啦？"
   · 简易进度标记（三档：读了一点点/读了好多/读完啦）
   · 金句收藏："今晚最喜欢的一句话"——孩子口述家长录入，或从该书
     热门划线 Top20 中点选（/book/bestbookmarks，如"5.7 万人划过这句"）
   · 心情贴纸（自主表达，不计分）
M5 落账（自动）
 └ 自动记录：日期/书/时长估算（M3→M4 间隔）/金句/心情
   → 连动成就灯：夜灯亮起第 N 晚（纪念册式，无奖励兑换）
```

### 2.2 家长端：共读卡 + 周报（MVP 核心）

**共读卡（每晚一张，随 M3 推送到家长端）**——吸收樊登小读者的"方法"内核，但基于今晚实际的书动态生成：

- **这本书**：简介/适龄提示/评分（/book/info）
- **讲什么**：3 个讲述要点（MVP 用模板 + 热门划线做锚点；V1 引入 LLM 基于目录与简介生成，人工模板兜底）
- **问什么**：3 个开放式问题（按年龄段梯度：3-5 岁事实性 → 6-8 岁推测性 → 9-12 岁评价性）
- **聊什么**：1 条"爸妈小时候"话题钩子（联结感的落点）

**周报（每周日晚自动生成，家长端 + 可分享图）**：
- 本周共读 N 晚 / 累计 X 分钟 / 完成书目（自采数据）
- 微信读书侧阅读统计对照（/readdata/detail：周/月维度）
- 最亮金句回顾 + 孩子的心情轨迹
- 下周建议（基于未读完的书 + 推荐）

### 2.3 家庭空间（轻量）

- 家庭书架视图：合并书架（/shelf/sync 的 books+albums+mp）+ 家庭自建"想读"清单；
- 多孩支持推迟到 V1.1（数据模型预留 `child_id`）。

### 3.2 V1.1（P1，Phase 2-3）

- LLM 共读卡（讲述要点/提问/话题钩子，模板兜底）；
- 金句收藏夹 + 年度纪念册导出（PDF）；
- 搜索选书（`/store/search` 九种 scope，孩子端语音输入）；
- "金句星球"：全书热门划线浏览 + 划线下的想法精选（`/book/underlines`、`/book/readreviews`）；
- 多孩档案；听书模式增强（albums 数据已有）。

### 3.3 V2（P2，Phase 4+，按数据决策）

- 家庭间轻社交：朋友在读（`/discover/interact/type3`，需评估隐私与攀比风险后决策）；
- 相似书推荐（`/book/similar`）驱动的"读完这本，下一本"；
- 微信小程序版（见 §4.2 形态论证）；
- 商业化验证（见 §9）。

### 3.4 负向清单（永远不做）

正文内容展示与缓存分发（版权红线）；积分兑换商城（过度合理化红线）；连续打卡断签惩罚（焦虑红线）；面向孩子的任何推送通知（防沉迷红线）；第三方广告（信任红线）。

## 4. 系统架构与技术选型

### 4.1 总体架构

```
┌────────────────────────────────────────────────────────────┐
│  孩子端 (PWA)          家长端 (PWA，同一应用的角色切换)        │

└───────────────┬────────────────────────────┬───────────────┘
                │ HTTPS (家庭码 + 设备态)      │
┌───────────────▼────────────────────────────▼───────────────┐
│  桃阅读服务端 (Node.js + TypeScript + Fastify)               │
│  ┌────────────┐ ┌────────────┐ ┌─────────────────────────┐  │
│  │ 仪式/记录    │ │ 共读卡/周报 │ │ 指挥官服务 (定时/推送)     │  │
│  └────────────┘ └────────────┘ └─────────────────────────┘  │

│  │  · key 解密与按家庭路由 (BYOK)   · skill_version 注入     │ │
│  │  · 响应缓存 (书架 10min / 书信息 24h / 统计 1h)            │ │
│  │  · 限频退避 + 熔断降级           · UTF-8 强制             │ │
│  │  · upgrade_info 响应处理                                  │ │
│  └────────────────────────────────────────────────────────┘ │
│  SQLite(开发/单家庭) → PostgreSQL(多家庭) + 对象存储(分享图)    │
└──────────────────────────┬─────────────────────────────────┘
                           │ HTTPS + Bearer wrk-***
┌──────────────────────────▼─────────────────────────────────┐
│  微信读书 Agent Gateway  https://i.weread.qq.com/api/agent/gateway │
│  (18 接口：search/shelf/book/stats/notes/review/discover)     │
└────────────────────────────────────────────────────────────┘
```

### 4.2 形态论证：为什么 MVP 选 PWA 而非小程序/原生

| 方案 | 优势 | 致命伤 | 结论 |
|------|------|--------|------|
| **PWA（H5）** | 双端一套代码；免审核快速迭代；孩子端可装到旧平板"独立窗口"；无平台抽成 | 需自备域名与托管 | ✅ **MVP 选型** |
| 微信小程序 | 微信内传播顺滑 | ① 个人主体类目难覆盖儿童阅读；② 小程序 web-view 打开 weread 链接受限，deepLink 唤起 App 体验不可控；③ 审核周期拖慢迭代 | ⏸ V2 按传播数据再评估 |
| Flutter 原生 | 体验最好 | 分发/审核/双端成本，对 MVP 过重 | ❌ |
| 桌面 Electron | — | 睡前场景不成立 | ❌ |

**deepLink 实测要点（Phase 0 必验）**：微信读书 web 链接（`https://weread.qq.com/book-detail?...`）在系统浏览器中可唤起 App 或降级 Web 版；在微信内置浏览器行为需实测；PWA 内跳转采用新开标签 + 引导浮层兜底。所有回包中的 deepLink 原样使用，绝不自行拼接（skill 规范）。

### 4.3 技术栈明细

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | React 18 + Vite + TypeScript + TailwindCSS；状态管理 Zustand；动画 Framer Motion（仪式感的关键投入）；PWA (vite-plugin-pwa) | 动画能力直接决定"仪式感"上限 |
| 后端 | Node.js 20 + TypeScript + Fastify + Prisma (SQLite→PG 可迁移) | 单人可维护；类型贯通 |
| 定时任务 | node-cron（周报/夜间汇总） | 简单可控 |
| LLM（V1） | OpenAI 兼容接口 + 模板兜底 | 共读卡生成 |
| 部署 | 家庭期：本地/内网穿透或 1 台轻量云（~¥50-100/月）；域名 + HTTPS 必备；国内正式服务需 ICP 备案（Phase 2 前完成） | |
| 埋点 | 自建轻量事件表（前端批量上报） | 儿童产品避免引入第三方 SDK（合规） |

### 4.4 数据模型（核心表）

```
family          家庭：id, code(家庭码), created_at
child_profile   孩子：id, family_id, nickname, avatar(本地图), stage(3-5/6-8/9-12), created_at
                （无任何真实身份信息；昵称头像家长端本地设置）
weread_binding  绑定：family_id, api_key_encrypted(AES-256-GCM), status, last_sync_at
book_cache      书籍缓存：book_id, title, author, cover, category, intro, chapters(json), deep_link, fetched_at
shelf_snapshot  书架快照：family_id, book_id, kind(book/album/mp), finished, read_update_time
cosession       共读记录：id, family_id, child_id, book_id?, paper_title?, started_at, ended_at,
                duration_sec, progress_mark(little/lot/done), mood, created_at
highlight_star  金句：id, family_id, child_id, cosession_id, source(weread/voice/manual),
                text, mark_count(多少人划过), created_at
achievement     成就：id, family_id, child_id, kind(night_lamp/streak_best/book_done), value, unlocked_at
parent_prompt   共读卡：id, family_id, book_id, stage, tell_points(json), questions(json),
                hook, gen_type(template/llm), created_at
weekly_report   周报：id, family_id, week_start, stats(json), share_image_url, created_at
event_log       埋点：id, family_id, role, event, props(json), ts
```

### 4.5 安全与隐私设计

1. **API Key**：AES-256-GCM 加密存储，主密钥环境变量/KMS；仅网关适配层运行时解密；任何接口不回显全文。
2. **儿童信息最小化**：不收集姓名/生日精确值/联系方式/位置；阶段（stage）三档即止；无第三方 SDK。
3. **访问控制**：家庭码（首登生成）+ 设备绑定；孩子端设备不持有家长端权限。
4. **传输与日志**：全站 HTTPS；日志脱敏（key、家庭码不入日志）。
5. **删除权**：家长端"注销家庭"一键抹除全部数据（合规审计要求，见调研 §6）。

## 5. 里程碑计划（20 周，单人 + AI 辅助）

### Phase 0 — 假设验证（W1-2）｜预算：≈0

| 周 | 任务 | 交付物 |
|----|------|--------|
| W1 | ① 5 个目标家庭访谈（含 1 个非用户家庭作对照），验证：睡前共读频率/痛点/选书权假设/脚手架需求；② 纸面原型（Figma 6 屏：仪式入口/选书/出发/收尾/夜灯/周报）；③ **技术三验**：deepLink 在微信内置/系统浏览器/旧安卓平板的唤起链路；网关限频摸底（连续 100 次调用观察 429/熔断）；听书专辑 deepLink 行为 | 访谈纪要 + 原型链接 + 技术验证报告 |
| W2 | 原型可用性测试（3 个孩子操作选书流）；Go/No-Go 评审 | Phase 1 开发范围冻结 |

**Go/No-Go 门槛**：≥3/5 家庭明确表示"愿意每周用 ≥3 次"；孩子能独立完成选书流；deepLink 至少一条链路成功率 ≥80%。**不达标 → 回到调研报告 §7.3 修正定位，不进入开发。**

### Phase 1 — MVP 开发 + 自家 Dogfood（W3-8）

| 周 | 任务 |
|----|------|
| W3 | 仓库初始化（monorepo：apps/web, apps/server, packages/shared）；CI（lint/test/build）；网关适配层（§4.1 全部职责）+ 缓存 + 限频退避 + 单测（mock 网关） |
| W4 | 绑定流程 + 家庭码 + 数据模型落地 + 书架同步 |
| W5 | 孩子端仪式流 M1-M3（重点打磨动画：月亮/骰子/出发倒计时） |
| W6 | 仪式流 M4-M5 + 夜灯成就 + 金句（含热门划线点选） |
| W7 | 家长端：共读卡（模板版）+ 周报 + 分享图；睡前时段与时长软限制 |
| W8 | 端到端联调 + 埋点 + 自家上线 Dogfood（连读 4 周，见门槛） |

**Go/No-Go 门槛（W12 复核）**：自家连续 4 周每周 ≥3 次孩子自主发起；跳转成功率 ≥80%；无 P0 缺陷。

### Phase 2 — 亲友内测（W9-12）

- 5-10 个 BYOK 家庭接入（每家庭自备 API Key，验证 BYOK 流程与 key 安全链路）；
- 周维度数据看板；A/B 观察激励设计（夜灯 vs 无夜灯两组家庭的发起频次差异，小样本定性为主）；
- ICP 备案、隐私政策与儿童保护规则页面上线（合规硬门槛）；
- 缺陷修复与性能（冷启动 <2s，动画 60fps 低端安卓）。

**Go/No-Go 门槛**：≥5 个家庭 4 周留存；≥50% 家庭的家长周报打开率 ≥3/4 周；收集 ≥20 条共读卡有效反馈。

### Phase 3 — V1 打磨（W13-20）

| 周 | 任务 |
|----|------|
| W13-14 | LLM 共读卡（含年龄段提问梯度）+ 模板兜底；金句收藏夹 |

**V1 发布门槛**：内测家庭周发起 ≥4 次；孩子端会话中位时长 ≤5 分钟；家长周维护 ≤15 分钟；合规自查全绿。

## 7. 合规与安全设计（对应调研 §6 清单）

1. **形态合规**：产品任何文案/界面/推送不得出现"课程、教学、培训、提高成绩、识字量承诺"；不设课时结构——规避"线上培训"认定与双减时长条款的结构性风险。
2. **防沉迷内生设计**：孩子端会话软封顶 5 分钟（超时进入"月亮睡了"收尾动画并锁定入口至次日晚间时段）；21:30 后孩子端入口自动进入"睡觉模式"；无任何面向孩子的推送。
3. **儿童个人信息**：不收集 <14 岁儿童身份信息（§4.4 已落实）；隐私政策含专门的儿童保护条款；监护人即家长账号，绑定动作视为监护人同意动作并留痕。
4. **内容适龄**：书架与推荐流经"童书类目白名单"过滤（category 前缀 1300000 童书等），家长可单书屏蔽；不展示成人类目内容。
5. **年度自查**：每年对照《未成年人网络保护条例》37 条做一次合规审计并留档（Phase 3 W18 建立 checklist）。

## 9. 成本与商业化预案（Phase 4 决策，不提前投入）

**成本**：开发期近乎零边际（自有设备 + AI 辅助）；运行期轻量云 ¥50-100/月 + 域名；ICP 备案免费（时间成本 2-4 周）。

**商业化候选（按与产品原则兼容度排序）**：
1. **免费+赞助式**（Khan Academy Kids 路线）：保持完全免费，靠分享图自然增长，积累家庭用户资产；
2. **家庭高级订阅**（¥60-120/年）：纪念册导出、LLM 共读卡深度、多孩——工具价值付费，不贩卖焦虑；
3. **出版合作**：基于家庭选书数据与优质童书榜单的出版合作分成（需规模化后）。

**红线**：不做广告、不做数据变现、不做孩子端任何付费诱导。
