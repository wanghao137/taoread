## 0. 第一性原理诊断（修前实测）

物理架构：源站 = 家庭服务器（cloudflared 隧道）+ CF 边缘 + R2（audio/media 域已迁 R2）。
源站代码本身快（127.0.0.1 实测 2.7ms TTFB）——慢全在「绕不开边缘」的传输路径上。
本轮主轴：重载荷（音频/JS/CSS/字体）离开家庭上行，由边缘/CDN 服务。

| 项 | 修前实测值 |
|---|---|
| index.html TTFB（晚高峰） | 1.6-5.0s，cf-cache-status: DYNAMIC |
| index 主 JS 边缘 MISS 回源 | 339 秒（225KB raw） |
| 音频 manifest | 17,872 条中 1,336 条 uploaded=false（走源站） |
| PhonicsGalaxy chunk | 554KB raw/133KB gz |
| 现代浏览器 polyfill | 100KB raw/40KB gz 白送 |
| 源站 TTFB | 2.7ms（216ms 为 localhost IPv6 解析伪影，已排除） |

## 4. 新增坑位（本轮实录）

1. **长 CJK+代码混排生成不稳**：设计/计划/代码多次输出乱码——解法=小块生成+读回校验+
   node --check；此坑与「GitBash node -e 吞 stdout」「heredoc 定界符被吞」同族
2. **e2e 端口占用须先辨识再动**：5173 监听者是用户另一项目的 vite（活跃工作），不可杀；
   用 TAO_E2E_WEB_PORT/TAO_E2E_API_PORT 隔离端口
3. **restart-api.cmd 不能在 GitBash 直跑**（timeout/find 被 MSYS 劫持、UTF-16 输出乱码）——
   nssm STOP/START 实际生效，但应改用 `cmd //c` + 事后 127.0.0.1:8091/api/health 验证
4. **测量脚本超时要包住 body 下载**：本轮 index-JS 339s 实测中 fetch 头 25s 内返回、
   arrayBuffer() 又下了 5 分钟——Promise.race 只包 fetch 不够，须整段（body 计入）

   一并修复
