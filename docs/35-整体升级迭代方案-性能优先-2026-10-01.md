# 35 · 桃阅读整体升级迭代方案（性能优先）· 2026-10-01

> 任务来源：用户反馈「整体故事、图片加载过慢、性能过慢」，要求从第一性原理出发做一次全面细致的整体升级迭代。
> 本文是**方案**（执行前评估），全部结论基于 2026-10-01 对生产环境（read.taostudioai.com / 127.0.0.1:8091）的真实取证测量，非推测。

---

## 一、第一性原理：这套系统的物理约束决定了性能天花板

桃阅读的部署形态是：**家庭 Windows 主机（Fastify + SQLite）+ Cloudflare Tunnel + R2 公共媒体桶（media.taostudioai.com）**。由此推出三条不可绕过的物理事实：

1. **家庭上行带宽（实测 ~95KB/s，差时 13KB/s）是全站最稀缺资源**。任何「公共、可缓存」的字节如果走了家庭链路而不是边缘/R2，都是架构违规——冷缓存时用户要为它等上秒级。
2. **Cloudflare 边缘缓存按扩展名默认缓存 GET**（实测 `/api/media/*.webp` 返回 `cf-cache-status: HIT`、`immutable` 一年）。这意味着：热资产已经很快，**慢的是冷穿透（回源走家庭上行）和从未被引用到边缘的资产**。
3. **书库内容（246 本书/2628 章/元数据）本质是静态内容**，但当前每次请求都做全表查询、全量 JSON 传输、且前端每次切 tab 都重拉——把静态内容当动态内容处理，是第二个系统性错配。

一句话诊断：**图片慢 = 关键路径上引用了「本地原档（310-479KB，冷穿透走 95KB/s 上行）」而不是「R2 变体（28-120KB，永不回源家庭）」；整体慢 = 书架接口 178KB 无压缩无缓存、每次切 tab 重拉 + 服务端全表查询。**

## 二、取证记录（2026-10-01，生产实测）

### 2.1 图片链路（用户痛点 #1 的直接原因）

| 资产 | 引用方 | 实测 | 链路 | 冷穿透耗时（95KB/s 上行） |
|---|---|---|---|---|
| 封面缩图 thumb 320w | 书架卡片（V8Cover 优先用） | **28KB** | R2 域 ✓ | 0（R2 兜底，不回源家庭） |
| 章节题图 reader 800w | 阅读器 hero（artReaderUrl） | ~120KB | R2 域 ✓ | 0 |
| **封面原档 2K** | **书籍详情页**（`src={book.cover}`=coverArtUrl 本地路径） | **310KB** | **本地 /api/media** | **≈3.3s** |
| **章节插图原档 2K** | **阅读器图片块**（blocks[].artUrl，无变体字段） | **479KB** | **本地 /api/media** | **≈5s/张** |

- 代码证据：`content/service.ts` 中 `variantUrl()` 只给封面 thumb 与章节题图 reader 挡生成 R2 外链；`artUrlFor()`（封面原档）与 `blocks[].artUrl`（插图原档）返回本地 `/api/media/...` 路径。
- CC-BY 绘本（44 本）每章含多个 image 块（全库 1,140 个图片块）——绘本恰恰图最多，受害者最集中。
- 本地路径的图片虽有 Cloudflare 扩展名缓存兜底（热态 HIT），但**每个边缘节点首次访问都要回源走家庭上行**；246 本书 × 章节图的冷矩阵永远铺不完。

### 2.2 书架接口（整体慢的主因）

```
GET /api/content/books?childId=…   200  本机冷 319ms / 热 153ms
  响应 163-178KB JSON，content-encoding: none（带 accept-encoding: gzip 也不压）
  cache-control: none
```

- 服务端：`listBooks()` 每请求 `db.book.findMany({ include: { chapters: { select: id } } })` **全量 246 本书连带章计数**，再逐书做适龄过滤/进度映射/屏蔽过滤/artMap 批查（246 个场景键 IN 查询）。
- 前端：`V8App` 的 effect 在 `/child`、`/child/today`、`/child/my`、`/child/discover` **每次路由切换都重拉**——孩子今天→找故事→我的→找故事逛一圈 = 4 次全量请求。
- 压缩缺失：`apps/server` 未安装 `@fastify/compress`；163KB JSON gzip 后约 25-35KB（缩 80%）。经隧道传输 uncompressed JSON 是纯浪费。

### 2.3 已确认良好的部分（不需要动）

- 哈希静态产物 `immutable` + SPA `no-cache`；PWA 外壳缓存（API/导航绝不缓存）。
- TTS 公共预生成走 R2（tts-public）；私有 TTS 段小（~40KB/段）+ SSE 逐段预取，可接受。
- 字体自托管 preload；封面三级回退（R2 缩图→本地→SVG）。

## 三、升级迭代方案

> 分四个轨道（A 图片链路 / B 数据与缓存 / C 阅读器与前端加载 / D 巩固与观测），共 14 个工作项。P0 = 直接决定用户感知，必须先做。

### 轨道 A：图片全链路走 R2（对应用户痛点 #1，预期收益最大）

**A1（P0）章节插图块暴露 reader 变体 URL，阅读器改用变体**
- `getChapter()` 的 blocks DTO 增加 `artReaderUrl`（复用 `variantUrl(map,'reader')`）；前端 image 块 `src` 优先 `artReaderUrl`，`onError` 回退 `artUrl`（本地）再回退 SVG 画框（沿用既有三级回退模式）。
- 效果：阅读器单图 479KB→~120KB 且永不回源家庭；CC 绘本一章 3 图从「冷 15 秒」变「边缘毫秒级」。
- 规模：S（半页代码 + 前端两处）。

**A2（P0）详情页封面改用 reader 档**
- 详情页 `src={book.cover}`（310KB 原档）→ `coverThumb ?? coverArtUrl` 改为「`coverReaderUrl`（新增 DTO 字段）→ coverThumb → coverArtUrl」回退链；原档仅保留在放大灯箱场景（灯箱可用原档，用户主动点击可等）。
- 规模：S。

**A3（P0）变体完整性审计 + 补齐**
- 脚本盘点：DB ArtAsset（3,067：246 封面 + 2,821 章节图）× 2 变体 × 本地存在 × R2 存在（`r2-inventory.mjs` 已可复用）；缺变体的跑 `gen-art-variants.mjs` 补、缺 R2 的跑 `sync-media-r2.mjs` 补。
- 产出一份「变体覆盖率 100%」的验收证据。
- 规模：M（主要是跑批与核对）。

**A4（P1）生成后自动同步 R2**
- 现状：`gen-art`/变体生成后需人工跑 `sync-media-r2.mjs`，期间新资产走本地冷穿透。改为：`artRoutes` 生成落盘后即触发单文件 R2 上传（复用 sync 脚本的上传函数，失败不阻塞响应、记日志待补）。
- 规模：S-M。

**A5（P1）加载体验细节**
- `index.html` 增加 `<link rel="preconnect" href="https://media.taostudioai.com">`（省 DNS+TLS 往返）。
- 阅读器 hero 图加 `fetchpriority="high"`（LCP 信号）；图片块补 `width/height`（或保持 aspect-ratio 容器，防 CLS——现状 16:9 容器已有，补 loading 状态占位即可）。
- 规模：S。

### 轨道 B：书架数据与接口（对应用户痛点 #2）

**B1（P0）启用 gzip 压缩**
- `@fastify/compress` 全局注册（`threshold: 1KB`）；**必须排除 SSE**（`/api/tts/chapter` 等流式路由——compress 对流式响应有已知干扰，用路由级 `config` 或对 `text/event-stream` 跳过；@fastify/compress 默认不压缩无 content-length 的流式回包，但需验证 SSE 心跳不被缓冲）。
- 验收：书架 JSON 178KB→≤40KB（传输字节）。
- 规模：S + 回归验证。

**B2（P0）书架客户端缓存：切 tab 不再全量重拉**
- `V8App` 改为：书架数据进内存（组件级或 zustand），路由切换**不再自动 refetch**；改为「阅读器结算返回 / 收藏切换 / 手动点刷新 / `visibilitychange` 回前台且距上次 >60s」时静默刷新（SWR 语义）。
- 保留 A10.5 的初衷（读完后进度贴纸要更新）——由「结算返回 today」这一明确时点触发。
- 规模：S-M。

**B3（P0）服务端目录缓存**
- 书目元数据（id/title/lang/category/ageStage/words/chapterCount/cover 场景键）在进程内缓存（Map + 5min TTL 或显式失效钩子：`seedAllPacks`/refresh/导入完成时清）。
- `listBooks` 只对「进度/收藏/屏蔽」做每请求查询（这些是真动态、量小：一个孩子的 ReadingProgress 行数 ≤ 在读书数）。
- 效果：热路径从「246 本全表 include + JS 过滤」变为「缓存数组过滤 + 3 个小查询」，本机热耗时 153ms → 目标 <30ms。
- 规模：M（含单测）。

**B4（P1）接口缓存协商**
- `/api/content/books` 增加 `ETag`（对「书目+适龄+childId」指纹）与 `Cache-Control: private, max-age=30`；304 短路进一步省流量（CF 不缓存带 Authorization 的响应，此头只作用于浏览器，正确）。
- 规模：S。

### 轨道 C：阅读器与前端加载

**C1（P1）下一章预取**
- 阅读器滚动超过 70% 时 idle 预取下一章 JSON + 题图（`requestIdleCallback`）；翻章从「点击后白屏等待」变「即时开章」。
- 规模：S。

**C2（P2）主包拆分**
- `index-*.js` 314KB（gzip 103KB）中 framer-motion 与路由/状态同包；把 framer-motion 拆出（动态 import motion 组件或 manualChunks）预期主包 -30~40KB gzip。低优先级，收益中等。
- 规模：M（回归动画链路）。

**C3（P2）legacy 插件复核**
- 确认现代浏览器不加载 polyfills chunk（`nomodule` 语义）；若现代浏览器也在拉 113KB polyfills 则修构建配置。取证一次即可。
- 规模：S。

### 轨道 D：巩固与观测（防退化）

**D1（P1）慢端点日志**
- Fastify `onResponse` 钩子记录 >500ms 的 API（路径+耗时+字节数）到 service-out.log（结构化一行），部署后自然积累 p95 证据，替代「感觉慢」。
- 规模：S。

**D2（P2）性能回归门**
- e2e 增加一条断言：书架响应 `content-encoding` 存在且传输字节 < 阈值；阅读器图片块 `src` 指向 media 域（防未来改回本地路径）。
- 规模：S。

## 四、明确不做（本轮边界）

- **不把私有家庭媒体（fam-import 插图、私有 TTS）搬 R2**：R2 公共桶全网可读，家庭私有内容出公共桶是隐私红线（docs/32 #2 的教训）；单家庭量小，走隧道可接受。
- **不做图片格式二次压缩/AVIF 重编码**：现有 2K→320/800 双档已覆盖需求，全库 MD5 零重复（09-28 实证），性价比低。
- **不上 CDN 图片 resizing 服务**：自产变体已等价，且避免引入按量计费项。
- **不做虚拟滚动**：书架每页渲染 60 张卡 + `loading="lazy"`，DOM 压力可控。

## 五、执行顺序与验收

| 批次 | 内容 | 验收标准 |
|---|---|---|
| 第 1 批（P0，当天） | A1+A2+A5、B1+B2 | 弱网模拟（Fast 3G）下：详情页首图 ≤130KB 且 URL 为 media 域；阅读器图片块全部 media 域；书架传输 ≤40KB；孩子端 today→discover→my 来回切换 **0 次重复书架请求** |
| 第 2 批（P0，次日） | A3 变体审计补齐、B3 目录缓存 | 书架本机热耗时 <30ms；变体覆盖率 100% 证据；verify/e2e 全绿 |
| 第 3 批（P1-P2） | A4 自动同步、B4 ETag、C1 预取、C3 复核、D1 日志、D2 回归门 | D2 断言进 CI；生产日志出现慢端点基线 |
| 收尾 | C2 主包拆分（视前三批收益决定是否做） | 主包 gzip -30KB 或放弃并记录原因 |

每批完成后：`npm run verify` + e2e 全绿 → 提交 → 部署 → 生产复测取证（对照本文第二节的数字）。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| gzip 干扰 SSE（TTS 整章流） | 注册时排除 event-stream；e2e + 真浏览器 TTS 回归（复用 .tao-tmp/browser-tts-verify.mjs 模式） |
| blocks 新增字段破坏旧客户端缓存壳 | PWA 外壳只缓存静态资产，API 不缓存，无影响；e2e 全量回归兜底 |
| 目录缓存与 seed/导入竞态（读到旧目录） | 失效钩子挂在 seed/refresh/导入完成的同一事务后；TTL 5min 兜底；audit.spec 已有内容断言 |
| R2 上传失败静默积压（A4） | 失败记日志 + `sync-media-r2.mjs` 幂等可重跑（既有工具链就是兜底） |
| 详见详情页换 reader 档后放大模糊 | 灯箱保留原档加载（点击时才拉，可等） |
