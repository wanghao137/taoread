# 桃阅读 v2 内容源接入方案评审（对用户方案的响应）

> 日期：2026-09-14 ｜ 输入：用户提供的《正文获取技术路线与公版书库方案》
> 方法：逐项实测（本机网络，即产品实际部署的家用环境）→ 评审修正 → 落地架构

---

## 0. 总体判断

**方案核心路线完全正确，照单接受：**

- ✅ 微信读书 = 账户/书架/进度/数据层，**不是正文源**（与我们对 17 个接口的实测一致）
- ✅ 路线 A（公版自建库）+ B（用户导入）为 MVP 主力；C（出版社授权）留作商业化远期；G（逆向私有接口）/H（OCR 截图）明确不做
- ✅ 统一 Canonical Book Format + **Rights Ledger（版权台账）**——后者是方案里最有长期价值的设计
- ✅ AI 儿童阅读体验（点词释义/分龄解释/朗读/理解题）作为核心壁垒——这正是"在工具里读"相对"跳去微信读书"的不可替代性

**但实测推翻了两个关键假设，落地计划据此修正（见 §1）。**

## 1. 实测修正（本机网络，2026-09-14）

| 源 | 方案评级 | 实测结果 | 修正后定位 |
|----|----------|----------|------------|
| zh.wikisource.org（Action/REST API） | 中文 S 级主库 | **HTTP 000 超时（大陆网络不可达，Wikimedia 全域被墙；dumps.wikimedia.org 同理）** | ❌ 不能作为直连源。改为：**海外 ETL worker 中转**（部署侧解决），MVP 期用「人工精选内容包」绕过 |
| Project Gutenberg（OPDS + 正文） | 英文主力 | **OPDS 200（60KB 可检索）/ 正文直下 200（爱丽丝全文 174KB）** | ✅ 英文主力源，实测可用 |
| Standard Ebooks（/feeds/opds/all） | 英文主力之一 | **HTTP 401**（完整 feed 需会员/开源项目条件——方案已预警，实测确认） | ⚠️ MVP 不依赖；后续按其政策接入 |
| 书格 shuge.org | 古籍 S 级 | **HTTP 403**（反爬拦截） | ⚠️ 只做人工挑选下载，不做自动接入（与方案"研究/古籍"定位一致） |
| ctext.org | 研究/核对源 | HTTP 200 可达 | ✅ 定位不变：核对用，不做默认正文源 |

**修正 1（关键）：中文内容的获取通道。** 维基文库在大陆不可直连，意味着「Wikisource API → 实时拉取」和「dump → 本地 ETL」两条路都需要海外中转。MVP 正确姿势：**人工精选 10-15 本中文公版书，一次性制成内容包打进仓库**（内容即代码，可审查、可离线）；规模化时再建海外 ETL worker。

**修正 2（关键）：中文儿童书的版权现实比方案描述的更紧。** 儿童真正爱读的白话童话/寓言，其通行中译本几乎全部在版权期内（译者逝世+50 年）。结论：**中文种子书只选"原文即公版且儿童可读"的**（蒙学、古诗、古典小说白话节选），**现代白话的儿童化呈现交给 AI 层实时生成**（释义/简化/朗读），而不是嵌入任何现代译本——这同时规避了翻译权地雷，又正好落在方案的 AI 壁垒上。

其余接受项：Gutenberg 中文书（三字经等）质量一般，不当中文主力；Google Books 只做元数据发现；CText 限流与再发布限制——均与方案一致。

## 3. 落地架构（对现有代码库的改造）

```
                ┌─ WeRead 层（现有，降级为可选增强）
                │   书架/进度/划线/推荐/成就对照
                │
Child Reader ───┼─ 内容域【新建】
                │   books / chapters / blocks（CBF 统一格式）
                │   rights_ledger（每书版权台账：作者/卒年/底本/来源URL/许可证/辖区/审核）
                │   内容包目录 content/（种子书，随仓库分发）
                │
                ├── 阅读器【新建，自研】
                │   React 渲染 blocks：翻页/字号三档/护眼底色/进度持久化
                │   （不嵌 epub.js——统一 CBF 后自研更贴合设计系统）
                │
                ├── 导入器【P1】EPUB/TXT 上传 → jszip+DOMParser 服务端解析 → CBF
                │
                └── AI 层【P2+】点词释义 / 分龄改写 / TTS(Web Speech) / 理解题
```

**复用不动**：孩子仪式流（选书→读→收尾→成就）、就寝/软封顶、家长端、周报、认证、PWA。
**deepLink 出发卡降级**：书籍来自内容域时直接进入内置阅读器；仅微信读书书架来的书保留跳转。

## 4. 分阶段计划

| **P3 AI 体验** | 分龄解释 / 章节问答 / 阅读理解题 / 家长报告增强（RAG over CBF） | 持续 |

## 5. 决策记录（我替你做的，可否决）

1. MVP 不做 Standard Ebooks 自动接入（401 实测），英文源只用 Gutenberg；
2. 中文种子书不收录任何现代译本，儿童化呈现全部走 AI 实时层；
3. 阅读器自研（CBF 优先），不引入 epub.js 渲染栈；EPUB 仅作为导入格式在服务端解析；
4. WeRead 集成保留但降级为可选（绑定与否都能用内容库）。
